## 全局声明

Pass1 面向整份程序，先把类型、函数和常量登记起来。同一份全局登记表会供各个函数共同使用。即使一个函数写在调用处后面，检查调用时也能找到它。

```rust
const N: usize = 2;
struct Point { x: i32 }
fn main() { let n = inc(1); }
fn inc(x: i32) -> i32 { x + 1 }
```

`Point` 提供类型声明，`N` 提供常量声明，`inc` 和 `main` 提供函数声明。登记名字时先确定它们各自是谁，随后再解析字段、常量类型与函数签名。`inc` 的签名说明它接收一个 `i32`，返回 `i32`，于是 `main` 中的调用有了检查依据。

`impl` 中的成员还要带上所属类型。两个结构体都能有名为 `read` 的方法，查找时需要区分 `Point::read` 与另一类型的 `read`。类型名字和值名字也按各自的规则查重；局部同名绑定则在 Pass2 中按作用域处理。

## 类型与常量

类型内部可以继续引用声明。数组长度尤其需要把名字查找和常量求值接起来。

```rust
struct Row { data: [i32; Row::N] }
impl Row { const N: usize = 2; }
```

登记 `Row::N` 后，字段类型里的路径就有了对应声明。不过，只有常量的名字和 `usize` 类型还不够。必须求出值 2，才能把字段确定为 `[i32; 2]`。因此 Pass1 会按依赖继续处理所需的信息，类型解析与常量求值可能相互穿插。

引用则继续解析所指类型，`Box`、`Vec` 继续解析元素类型，`Self` 根据当前所属类型解释。函数参数与返回类型都确定后，签名才能完整供调用处使用。

## 声明的成立条件

字段类型确定了，还需要确认对象可以用有限存储表示。字段若直接包含自身，会不断要求再放一个完整对象；引用或容器可以改变这种存放关系。

```rust
struct Bad { next: Bad } // 无法有限展开
#[derive(Clone)]
struct Tree { children: Vec<Tree> }
```

`Tree` 的对象大小可以有限确定，但 `derive(Clone)` 还需要沿字段检查克隆能力。大小检查与能力检查各自使用字段类型，判断的条件不同。常量也需要检查依赖是否成环，不能仅凭名字可查就认为能够求值。

最后还要确认存在符合要求的顶层 `main`。名字、声明类型、所需常量值以及这些成立条件一起确定后，函数体中的使用才有可靠依据。Pass1 中遇到错误仍会尽量查看其他声明，已记录的错误会阻止程序进入正常代码生成。

**登记名字只是起点，声明上的类型、值和限制还要逐项成立。**
