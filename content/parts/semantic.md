## 语义分析的两项工作

现在我们来讨论编译器的语义解析器。

语义解析器主要解决了两件事情：

1. **收集与注册符号，并检查声明结构。**
2. **检查表达式的合法性，并记录表达式的语义事实。**

## 表达式的对齐

一个最基本的认识是Rust这个语言具有以表达式为中心的性质，也就是 **“Everything is an expression”**，语义解析器的一条核心主线是表达式的对齐。

Rust这门语言中的很多结构都是表达式，包括 `if`/`loop` 等控制流、函数体等等。正常返回的表达式具有结果类型，包括 `Unit`；无法正常返回的表达式具有 `Never` 类型。结果类型要对齐，可变权限要对齐。当前讨论的范围未实现完整的生命周期与所有权检查。
```rust
fn choose(flag: bool) -> i32 {
    if flag { 1 } else { return 2; }
}
```

第一件事先确定 `choose` 的参数是 `bool`，返回类型是 `i32`。第二件事才进入函数体：条件 `flag` 要满足 `bool`，正常结束的分支要给出 `i32`。

`return 2` 直接离开函数，自身具有 `Never` 类型；它携带的 `2` 仍需符合函数的返回类型。若把 `2` 改成 `true`，就会发生类型不匹配。`Unit` 则表示正常结束但没有额外数据，例如空块 `{}` 的结果 `()`。

**先明确名字和声明，再沿表达式检查类型与权限，这两件事构成语义分析的主线。**
