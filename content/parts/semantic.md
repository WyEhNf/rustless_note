## 声明与表达式

AST 已经把声明、语句和表达式组织起来。语义分析沿着这些关系继续检查：名字对应哪个声明，类型能否配合，当前位置能否进行相应操作。

这里的工作分为两遍：**Pass1 收集与登记声明，并确定声明上的要求；Pass2 进入函数体，检查每一次具体使用。**

```rust
fn inc(x: i32) -> i32 { x + 1 }
fn main() {
    let value = 1;
    let answer = inc(value);
}
```

读到 `inc(value)` 时，需要知道 `inc` 接收什么类型、返回什么类型。这些要求来自函数声明，可以在检查 `main` 之前准备好。结构体字段和常量也有声明上的要求，同样需要先取得明确的含义。

进入 `main` 后，`value` 和 `answer` 才依次成为可见的局部名字。调用中的 `value` 找到前面的绑定，取得 `i32` 类型，正好满足 `inc` 的参数要求。调用又根据返回类型为 `answer` 提供 `i32`，声明与使用就这样联系起来。

## 表达式的结果

Rust 风格语法中的许多结构都能提供结果。函数体是块表达式，`if` 可以从分支取得值，`loop` 可以由 `break` 带出值。外层表达式需要使用这些结果，因此检查会从整体进入孩子，再根据孩子的结论确定整体。

```rust
fn choose(flag: bool) -> i32 {
    if flag { 1 } else { 2 }
}
```

`flag` 决定选择哪条分支，需要是 `bool`；两条分支提供函数要求的整数。条件和分支都属于表达式，但在整个 `if` 中承担不同作用，检查要求也随之不同。

**表达式之间已经有结构上的连接，语义分析让这些连接具有明确的名字、类型和使用要求。**

名字查找需要全局声明和当前作用域，检查所得的结论还需要按节点保留下来。[语义分析流程与记录](/posts/5.0)先用一份程序说明这几类信息怎样配合。读到具体规则时，可以继续沿 Pass1 的声明准备和 Pass2 的函数体检查展开。
