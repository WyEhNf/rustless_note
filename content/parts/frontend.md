**从源码到AST的转化是编译器工作的第一步，这是一次语法上的变换。**

## CST 与 AST

AST 来源于 CST。编译器首先对一段程序进行**词法和语法上的分析**，从语法的角度对程序文本做一个结构上的编排，这就得到了 CST。随后遍历 CST，递归地构建每个节点，把其中的具体元素整理成 AST。

```rust
fn main() {
    let x = 1 + 2 * 3;
}
```

读词时可以认出 `let`、`x`、`+` 等内容。语法分析进一步确定：乘法先组成一组，加法的右边是整个 `2 * 3`。转成 AST 后，就沿着这个关系留下函数、块、绑定和运算。

**AST 把程序的结构留下来，语义分析再检查这些结构能否配合。**

## Crate 与 Item

AST 的根节点是 **`Crate`**，包含整份程序的顶层信息。其内部按顺序保存若干 **`Item`**，也就是声明单元。当前主要讨论五类：

1. **`Use`**：保存导入的写法，例如 `use std::collections::HashMap;`。它描述希望建立的名字关系；当前范围还没有完整的模块导入查找。
2. **`Struct`**：声明结构体，说明它有哪些字段。
3. **`Const`**：声明常量，说明常量的类型和初值。
4. **`Impl`**：说明一组关联函数、方法和常量属于哪个类型。
5. **`Function`**：声明函数，说明参数、返回类型和函数体。

```rust
struct Point { x: i32 }
const LIMIT: i32 = 10;
impl Point {
    fn get(&self) -> i32 { self.x }
}
fn main() { let p = Point { x: 1 }; }
```

这里的顶层依次是结构体、常量、`impl` 和函数。`get` 是 `Point` 的关联成员；`let p` 则在 `main` 的函数体里。从根向下阅读时，先看到这些声明，再进入各自的内容。

## Type 与类型嵌套

结构体、常量和 `impl` 都会用到类型：可能是字段的类型、声明的类型，也可能是关联成员所属的目标类型。函数参数和返回值、局部变量的类型标注，也需要 **`Type`**。

`Type` 本身具有嵌套结构。类型可以由其他类型组合，组合出来的类型又能被继续使用，因此会形成一棵类型子树。

```rust
let rows: &mut Vec<[i32; 3]>;
```

从外向内看，`rows` 是一个可变引用，指向 `Vec`；`Vec` 中的每个元素是长度为 `3` 的数组，数组元素才是 `i32`。每一层都说明了不同内容，需要逐层保留。

**`Type` 会出现在 AST 的多处，不能只把它放在某个固定层级里理解。**

## Block 与 Stmt

函数内部由块表达式 **`Block` `Expr`** 构成。块里按顺序保存若干 **`Stmt`**，也就是语句。这里主要有局部绑定 `let`、表达式语句，以及块末尾的尾表达式；单独的分号还可以形成空语句。

```rust
fn add_one(x: i32) -> i32 {
    let y = x + 1;
    y
}
```

`let y` 引入局部名字，初值是加法表达式。最后的 `y` 没有分号，给这个块提供结果，函数也就返回它。若改成 `y;`，这个值会被丢弃，块正常结束时得到 `Unit`，便无法满足声明中的 `i32`。

函数和内层块还会影响名字的可见范围，这个范围叫 **`scope`**。建树先留下块和语句的关系；具体哪一次名字使用能找到哪条声明，要到语义分析时检查。

## Expr 的递归嵌套

`Stmt` 中的初值和计算内容主要由 **`Expr`** 组成。`Expr` 表示表达式，需要按其种类继续讨论：

- **基础值与聚合值**：整数、布尔值和 `Unit` 是基础值；数组、结构体等把若干值放在一起。路径则通过名字找到要使用的内容。
- **分支与循环**：内部带有块表达式；`if` 和 `while` 的条件本身也是表达式，因此形成递归嵌套。
- **跳转**：`break`、`continue`、`return` 改变程序接下来执行的位置，还可能携带一个表达式。
- **运算与转换**：一元运算、二元运算、赋值和类型转换。连续转换要逐层保存，最外层决定最终结果类型。
- **后缀表达式**：`()` 调用函数，`.` 访问字段或调用方法，`[]` 访问元素。调用的实参仍然是表达式。

```rust
let n = if ready { values[0] + 1 } else { 0 };
```

整个初值是 `if`。它包含条件 `ready` 和两个块；第一个块的尾值是加法，加法左边又是下标访问。这里从 `Expr` 走进 `Block`，再走回 `Expr`，就能看出递归关系。遇到 `.get()` 时，还要保留方法调用；只写 `.x` 时，则是字段访问。

## Primary 与叶子

**`Primary`** 表示文法中可以继续参与运算的基本写法，主要包括字面量、路径和括号表达式。

```rust
1
x
(x + 1) * 2
```

整数 `1` 和路径 `x` 可以直接成为基本节点。第三行的 `(x + 1)` 也能作为乘法左侧的 `Primary`，但其中仍然包含加法。括号确定的分组可以由 AST 的父子关系保留。

从树的底部看，常见叶子是字面量和路径：字面量直接写出值，路径通过名字找到声明。`Primary` 的范围还包含括号包住的复杂表达式，所以阅读时要分清**文法中的基本写法**与**树中已经没有表达式孩子的叶子**。

当前类型路径可以找到内建类型和用户结构体。类型别名需要额外的声明与查找规则，这里暂不展开。

## 编译期参数与整棵树

`Item` 还可能带有泛型参数、生命周期参数和 `where` 约束。这些属于编译期信息：类型参数说明可以换入什么类型，生命周期参数给引用有效期起名字，约束说明这些参数需要满足什么要求。当前范围只保存其中一部分信息；这些名字能出现在语法树中，还不足以完成通用泛型或引用有效期的检查。

AST 可以先沿下面这条主干理解。父子之间通过列表或对象连接组织起来，各类节点再保存自己需要的内容。

```text
Crate：整份程序
└─ Item：导入、结构体、常量、impl、函数
   ├─ Type：字段、参数、返回值等类型
   ├─ 编译期参数：泛型、生命周期与约束
   └─ 函数体 Block
      ├─ Stmt：let、表达式语句、尾表达式
      │  └─ Expr：值、运算、调用、分支、循环、跳转
      │     ├─ 更小的 Expr
      │     ├─ Block → Stmt → Expr
      │     └─ Type：转换目标或类型实参
      └─ 常见叶子：字面量、路径
```

**这条主干帮助我们读树，递归关系决定了它还可以继续向下展开。**

从源码进入这棵树时，先确定词与文法的分组，再按声明、类型和表达式逐层整理。结构保留下来以后，语义分析就能沿这些连接查名字、比较类型。
