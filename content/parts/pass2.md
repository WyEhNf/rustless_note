## 函数体中的名字

Pass2 按函数检查执行内容。函数签名已经说明参数类型和返回要求，进入函数体后，参数成为局部绑定，随后出现的 `let` 再逐条加入当前作用域。

```rust
fn inc(x: i32) -> i32 {
    let y = x + 1;
    y
}
```

检查初值 `x + 1` 时，`x` 找到参数声明；初值检查完成后，`y` 才能被后面的语句使用。末尾的 `y` 提供函数体的结果，仍要满足签名中的 `i32`。进入内层块会增加一层查找范围，离开后恢复外层；同名绑定的生效顺序就在这个过程中确定。

函数体还可能包含循环。`break` 和 `continue` 需要知道所在循环，`return` 需要知道当前函数的结果要求。这些信息与局部名字一起构成检查表达式时的上下文。

## 类型要求的传递

表达式的外层经常已经知道需要什么类型。这个要求称为 `expected`。例如函数签名规定实参类型，结构体声明规定字段初值类型，带标注的 `let` 规定初值类型。

```rust
fn take(x: u32) {}
fn main() {
    take(1);
    take(true); // 实参类型不符
}
```

第一个调用可以用参数的 `u32` 要求确定整数 1 的类型。第二个调用也提出同样要求，但 `true` 自身具有 `bool` 类型，因而无法匹配。要求沿表达式结构传递，实际结论又从孩子返回整体；具体传给哪些孩子，要看表达式的形式。

数组把元素要求交给各个元素，块从尾部取得结果，分支与循环还要考虑哪些路径正常结束。类型有差异时，部分位置允许隐式借用等调整，这些步骤需要随检查结果保留。

## 访问与调用

有些操作还会修改已有的值。此时除了类型相符，还要确认访问允许写入。

```rust
struct Point { x: i32 }
impl Point {
    fn read(&self) -> i32 { self.x }
    fn bump(&mut self, d: i32) { self.x += d; }
}
fn main() {
    let p = Point { x: 1 };
    let n = p.read();
    p.bump(1); // p 的绑定不可写
}
```

`read` 需要共享接收者，`bump` 需要可变接收者。两次调用都能找到方法，也都能得到明确签名，但接收者要求不同。字段、下标、借用和赋值会继续遇到这种访问问题，因此需要保留从对象到内部位置的访问限制。

## 检查结果

每次名字使用都会确认它对应哪个声明，每个表达式都会得到自己的类型与使用结论。调用还留下目标及隐式调整；类型标注留下解析结果。局部作用域退出以后，这些按节点保存的信息仍然存在，后续处理可以直接使用。

**Pass2 沿着函数体逐项检查，再把每次使用已经确认的含义留在相应节点上。**

理解局部上下文和类型要求后，字面量、构造、控制流、运算与调用就可以逐类展开。它们共用这些依据，同时各自规定孩子怎样参与检查、整体怎样得到结果。
