## place 与可写性

赋值首先需要一个能定位到存储位置的表达式，这叫 `place`。找到位置以后，再问能不能写入，这两个问题需要接着判断。

```rust
let x = 1;
let mut y = 2;
x = 3;       // 不可写
y = 3;
(y + 1) = 4; // 加法整体没有赋值位置
```

`x` 与 `y` 都有对应位置，区别是绑定权限。`y + 1` 读取 `y` 参与计算，整体产生一个临时值，无法直接作为赋值目标。`p.x`、`a[i]`、`*r` 可以进一步定位字段、元素或引用目标，仍需要沿访问路径确认权限。完整语言还会把这些性质用于移动与借用分析。当前的 `place` 检查不能直接等同于已经具备完整所有权检查。

### 绑定权限与引用权限

引用又把权限分成了两层：能否给引用变量重新赋值，以及能否经引用修改它指向的值。`let mut` 与 `&mut` 分别影响这两件事。

```rust
let x = 1;
let y = 2;
let mut r = &x;
r = &y;
let mut n = 3;
let s = &mut n;
*s = 4;
```

`r` 可以换成指向 `y`，因为绑定可变；但 `r` 仍是共享引用，不能经它修改目标。`s` 的绑定没有 `mut`，不能随意重新给 `s` 赋一个引用值；它保存的是可变引用，因此可以经 `s` 修改 `n`。字段和下标访问也要区分这两层权限。只看最外面的 `let` 是否带 `mut`，会错过第二种合法访问。

**能改引用变量，和能改引用指向的值，是两层权限。**

### 访问路径的限制

继续套上多层引用时，还要记住此前经过的访问限制。只看到里面的 `&mut`，就可能漏掉外层共享访问带来的约束。

```rust
let mut n = 1;
let r = &mut n;
let shared = &r;
**shared = 2; // 错误
```

沿 `shared` 的第一步是共享访问，已经限制修改。第二步看到内部 `&mut i32`，不能清除外层留下的限制。同样，通过不可写 `Vec` 取出可变引用元素时，也需要保留受限来源。否则后面再解引用，就可能错误地允许写入。这类访问限制可以记作 `access_locked`，描述当前路径已经受到共享访问约束。后续可变借用、赋值或需要 `&mut self` 的方法都要读取这个结论。它记录的是这条路径，完整借用冲突与引用有效期还需要其他检查。

## 借用与解引用

一元表达式只有一个主要操作数，不过各种操作要检查的事情不同。借用先涉及类型与访问权限，多层借用还需要从外到内分清楚。

```rust
let mut x = 1;
// 分别观察下面各行的类型：
&x;       // &i32
&mut x;   // &mut i32
&&x;      // &&i32
&&mut x;  // &(&mut i32)
```

最后一行先形成可变引用，再对这条引用作共享借用。因此里面带 `mut`，外层依然限制共享访问。借用位置的 `&&` 与布尔运算 `a && b` 属于不同语法用途，要结合出现位置区分。可变借用会拒绝不可写位置和**受限路径**。当前规则没有一概拒绝所有临时值，所以不能直接把“没有名字”当成唯一失败理由。

解引用沿引用或 `Box` 找到内部值，也可能得到可以定位的位置。之后是否允许写入，仍要沿这条访问路径继续判断。

```rust
let mut x = 1;
let r = &mut x;
*r = 2;
let b = Box::<i32>::new(3);
let value = *b;
*1; // 错误：整数不能这样解引用
```

`r` 是可变引用，所以 `*r` 可以修改 `x`。`*b` 沿 `Box` 取得内部整数；`*1` 则没有可解开的引用或容器。当前显式解引用只接受引用或 `Box`。`Box` 的内部访问还要结合持有它的表达式权限。得到 `place` 以后，赋值依然要检查可写性。把“能解引用”直接理解成“能赋值”会省掉这一步。

负号和感叹号处理的则是值本身。它们需要根据整数、布尔等类型选择具体规则，不能直接套用借用与解引用的检查。

```rust
-1i32;
-1u32; // 当前规则拒绝无符号取负
!true; // bool，结果 false
!1i32; // i32，逐位取反
```

取负保留有符号整数类型。布尔取反交换真假，整数取反则改变各二进制位，不能把两者都理解为同一种数值计算。当前部分标量运算可以先剥去一层共享引用，再检查内部整数或 `bool`；更深的引用层不能因此一概视为支持。因此先得到操作数类型，再按具体符号选择要求，才能确定结果类型。
