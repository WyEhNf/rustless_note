## 调用目标

这一章讨论函数调用。可以把检查过程概括成：先确定括号前面表示哪个可调用对象，再读取签名，按参数要求检查实参，最后留下结果类型与具体目标。

```rust
fn positive(x: i32) -> bool { x > 0 }
let ok = positive(3);
let bad = positive(true); // 实参不符合 i32 要求
```

名字 `positive` 先找到函数声明，声明给出接收一个 `i32`、返回 `bool` 的签名。3 在这个要求下取 `i32`，调用得到 `bool`。`true` 固定为 `bool`，因此第二次调用即使找到了目标，也无法满足参数要求。如果括号前面是普通整数，则还没有一个可调用目标。

函数类型可以通过名字或声明身份找到完整签名。仅知道“这是函数”，还不能猜出有几个参数、每个参数是什么类型。调用检查完成后也要保留调用的是谁，同样返回 `i32` 的两个函数仍然可能做不同的事。

## 形参与实参

参数先按位置对应，逐个取得 `expected`，继续检查实际类型、允许的适配以及必要的写权限。参数数量错误时，也可以继续查看已经给出的实参，以便同时发现其中独立的类型或名字问题。

带 `self` 的方法还多一个接收者。点语法把它写在点号前面，显式关联调用则需要把相应值或引用放到实参最前面。方法需要共享接收者时，`Point::read(&p)` 就明确提供了这一部分。

## 内建调用

```rust
let n = getInt();
let mut values = Vec::<i32>::new();
Vec::<i32>::push(&mut values, n);
printlnInt(n);
```

`getInt` 没有值参数，结果是 `i32`；`printlnInt` 接收 `i32`，结果为 `Unit`。`Vec` 的类型实参说明元素类型，`new` 创建 `Vec<i32>`，`push` 再要求可变 `Vec` 引用和一个 `i32` 元素。

`Box` 和 `Vec` 采用专门的内建规则，构造时要求明确的类型实参，普通用户函数的通用类型泛型还没有因此自动具备。容器的 `len`、`remove`、`clone` 等操作也分别规定参数、权限、返回类型和能力要求，不能仅凭名字相近推广到其他容器。

## 检查与执行

语义检查确认 `push` 应当怎样调用，但不会在这个阶段真的增加元素。程序运行时还需要读取容量，必要时扩展存储，放入元素并更新长度。这些实际动作由后面的生成过程与运行时支持共同完成。

**签名说明这次调用需要什么，调用记录说明最后确定了谁、得到什么，以及需要哪些调整。**

本章先把目标查找与签名检查放在一起，再集中讨论输入输出和容器接口，最后区分检查过程与运行时操作。点 `clone` 和显式关联 `clone` 在当前检查中的差别，也会保留具体例子，避免把某种写法被接受直接当成完整能力保证。
