## 块的顺序

块中的**语句按顺序检查**，这个顺序决定某个名字何时可见。检查走到最后，还要根据尾部写法确定整个块的结果。

```rust
fn value() -> i32 {
    ;
    let x = 1;
    x
}
```

空语句跳过。`let` 按[局部绑定顺序](/posts/9.2)登记 `x`。最后一个无分号表达式 `x` 接收块的 `i32` 要求，成为结果。普通带分号表达式计算后丢弃值。处在非末尾的无分号表达式，需要满足当前允许的 `Unit` 或 `Never` 规则。若末尾写成 `x;`，正常结果变成 `Unit`，无法满足这里的 `i32` 返回要求。

末尾是 `return` 时，需要把 `Never` 一起考虑。不过，当前对末尾的处理还不能代表已经完成任意位置跳转的可达性分析。

```rust
fn a() -> i32 { return 1; }
fn b() -> i32 { return 1; let x = 2; }
```

`a` 的最后表达式是 `Never`，能够满足函数结果要求，实际返回值由 `return` 中的 1 提供。`b` 在 `return` 后还有语句。完整的可达性分析可以知道后缀不会执行，但当前块规则主要依据最后一项，没有完整传播所有早期跳转的影响。因此“末尾 `Never` 会保留”有明确范围，不能据此推断任意位置的 `return` 都已完成同样的后续路径分析。

## 分支结果

`if` 的条件和两个分支都是表达式，但角色不同。条件回答走哪一条路，分支才为整个 `if` 提供结果，所以接收的类型要求也不同。

```rust
let flag = true;
let x: u32 = if flag { 1 } else { 2 };
let y = if 1 { 3 } else { 4 }; // 条件类型错误
```

`x` 的条件按 `bool` 检查，两支数字各自得到 `u32` 期望，最终形成 `u32` 的 `if` 结果。`y` 的分支都是整数，却不能补救条件中的 1。条件是独立的子表达式，需要满足 `bool`。这说明 `expected` 的传递要区分孩子的角色：同一个 `if` 内，**条件与结果分支接收不同要求**。

如果没有 `else`，还要考虑条件为 `false` 的路径。这条路没有执行 `then`，自然也拿不到 `then` 里算出的值。

```rust
// 每行分别放入 flag: bool、count: i32 可见的函数体；count 可变。
if flag { 1 }  // 错误：then 留下整数
if flag { 1; } // 正常结果为 Unit
if flag { count += 1; }
```

第一行在条件真时得到整数，假时却没有对应整数。第二行用分号丢弃 1，整个 `if` 可以正常得到 `Unit`。赋值表达式本身也得到 `Unit`，因此第三行适合表示有条件地做一次修改。`then` 如果跳走而成为 `Never`，也不会增加另一种正常结果。整个没有 `else` 的 `if` 仍按 `Unit` 理解。

补上 `else` 后，两边都能说明自己的结果。此时再结合适配和 `Never`，判断正常结束的路径能否给出共同类型。

```rust
fn choose(flag: bool) -> i32 {
    if flag { 1 } else { return 2; }
}
```

`else` 直接返回函数，因此只有 `then` 会正常到达 `if` 的末尾，整体结果可以是 `i32`。两支都正常给出值时，再使用[共同类型的适配规则](/posts/10.2)。这里新增的判断在于哪些路径能够到达 `if` 末尾：正常结果需要共同类型，提前返回的路径则没有这个正常结果。
