## 命名空间与查找范围

第一遍先把声明名字收集起来，让后续解析有地方可查。这里区分**类型命名空间和值命名空间**：可以把它们理解成两类各自查重、各自查找的名字集合。

```rust
struct Point { x: i32 }
fn Point() {}
const Point: i32 = 1; // 与函数的值名字冲突
```

在当前规则下，结构体 `Point` 提供类型名字，函数 `Point` 提供值名字，可以分别登记。再出现同名常量，就与函数争用同一个值名字。顶层扫描先收集声明，`impl` 还需要等目标类型确定后再处理成员。字段和函数体可以稍后继续检查。即使发现重复仍继续收集其他错误，最终结果也不能忽略已记录的冲突。局部 `let x` 的遮蔽由函数体中的作用域规则决定。

### 受保护的内建名字

有些名字已经由语言内建规则使用，声明时还需要额外检查。当前讨论的输入输出函数就属于这种情况。

```rust
fn getInt() {}       // 错误：受保护的名字
fn main() {
    let printInt = 1; // 错误：受保护的名字
}
```

`getInt`、`printInt`、`printlnInt` 是这里保护的正式输入输出名字，相关函数、常量、参数和局部绑定都需要检查。`i32` 与普通名字 `x` 在读词时都可能属于标识符。到了类型位置，才进一步识别 `i32` 是内建整数类型。`Box`、`Vec` 与四种支持的 `derive` 名也有各自检查。

兼容写法 `get_i32`、`print_i32`、`println_i32` 的识别范围与正式名字的保护范围有差别，不能由“能调用”直接推断“所有同类名字都受相同保护”。

## 关联成员

`impl` 自己没有一个供调用的名字。处理它时，需要先找到后面写着的目标类型，再把里面的函数和常量归到这个类型下面。

```rust
struct Point { x: i32 }
impl Point {
    fn zero() -> Self { Point { x: 0 } }
}
```

`Point` 已作为结构体登记，因此 `zero` 可以归到 `Point` 下面，结果类型 `Self` 也可以解释为 `Point`。找到目标名字时，不必先把 `Point` 的每个字段都检查完。**先确定声明身份**，再继续处理字段与方法签名，能够容纳前后相互引用。

如果写成 `impl Missing { ... }`，却没有对应结构体，所属关系就无法建立。当前范围也不能把任意类型都当成可声明用户 `impl` 的目标。

确定所属关系之后，关联成员要尽早登记。有些字段类型会用到写在后面的关联常量，提前登记就能让这种依赖有处可查。

```rust
struct Buffer { data: [i32; Buffer::N] }
impl Buffer {
    const N: usize = 3;
    fn size(&self) -> usize { Self::N }
}
```

读 `data` 的数组类型时，需要 `Buffer::N` 的值。若已经登记这个常量，就可以继续求得 3，确定字段类型。`size` 中的 `Self::N` 也会转为 `Buffer::N`。成员查重既要看同一个 `impl` 内，也要看同一类型的多个 `impl` 之间。函数与常量成员同名同样可能冲突。把成员写到另一个 `impl` 块，并不会给它换一个所属类型。

登记的内容来自实际声明。对于使用处写出的路径，再根据完整关联名查找即可，不必猜测程序以后可能写出哪些名字。

```rust
struct Point { x: i32 }
impl Point { fn get(&self) -> i32 { self.x } }
fn main() { Point::missing(); } // 错误：没有这个成员
```

表里可以有 `Point::get`，无需提前添加 `Point` 下所有可能出现的名字。查询 `missing` 失败后，就说明没有对应声明。完整名字用于哈希查找。平均查表探测次数可以很少，但拼接路径和计算字符串哈希仍然需要读取名字内容。当前这里只讨论结构体关联项。任意深度的模块路径还需要逐层确定模块和可见性，不能直接由关联表推断已经支持。
