## 词与文法

拿到一段程序，编译器先要认出里面的词，再看这些词能组成什么结构。词的边界与表达式的分组分别确定，二者共同影响留下的节点。

```rust
let x = 1 + 2;
let y = 1 + true; // 语法完整，类型不合适
```

`Lexer` 是**词法分析器**，把 `let`、`x`、`=`、`1`、`+`、`2`、`;` 分成 `token`，也就是一个个词。`Parser` 是语法分析器，按文法认出局部绑定和加法。文法规定程序可以怎样写。CST 是具体语法树，保存规则之间的嵌套。`AstBuilder` 读取 CST，整理成 AST，也就是抽象语法树。一个对象叫节点，连接的下一层叫子节点，最上方叫根。

第一行留下名字 `x`、加法和两个整数。第二行也能组成这样的结构，但整数与布尔值不能直接相加，这要在 `semantic`，也就是语义分析中发现。

这些结构由**文法**规定。`ANTLR` 可以读取 `.g4` 文件中的文法，生成 `Lexer` 和 `Parser`；生成出来的工具读到具体源码后，才会得到这次输入的树。

```antlr
sum : NUMBER ('+' NUMBER)* ;
NUMBER : [0-9]+ ;
```

`NUMBER` 规定数字由一位或多位数字组成，`sum` 规定数字后可以反复接上“加号和数字”。这里的大写名字对应词法规则，小写名字对应语法规则。读到 `1 + 2 + 3` 时，`Parser` 按 `sum` 组织这三个数字。读到 `1 +` 时，加号后缺少数字，就无法完整匹配。

`*` 表示零次或多次，`+` 表示一次或多次；`?` 表示可选，`|` 表示从几种写法中选择。这些符号用来写规则，源码中的加号则写在引号里。

文法还需要说明哪些部分先组成一组。加法和乘法就是一个很直观的例子。

```rust
1 + 2 * 3
(1 + 2) * 3
```

第一行的最外层是加法：左边是 1，右边是一整棵 `2 * 3`。第二行的最外层变成乘法，左边先保存 `1 + 2`。只看从左到右的词，还需要文法才能决定这两种层次。构造 AST 时顺着已经识别的子树往下走，就能保留分组。访问一个节点的直接孩子，只会看到下一层；继续递归才会看到孙子节点。顺序遍历负责收集同层内容，递归负责进入更深的结构。

**文法规定允许怎样写，具体的树再把这次输入的分组留下来。**

## 节点信息

CST 中的 `Context` 可以理解成**已经识别出来的一段语法**。大段里面还套着小段：函数里有函数体，函数体里有表达式。转成 AST 时，就沿着这些关系往下读。

```rust
fn add(x: i32) -> i32 {
    (x + 1)
}
```

整个文件包含函数声明，函数包含参数、结果类型和函数体，函数体再包含加法。每一层都可以由对应的 `Context` 保存。声明、语句和表达式分别由对应规则识别，再按例子中的包含关系连接。括号确定 `x + 1` 的分组。

进入 AST 后，可以直接保留加法及两个孩子，括号的作用已经体现在结构里。`x as u32` 则确实多了一次转换，需要保留这次操作。

结构整理出来以后，还需要区分源码中每一次出现的位置。同样一个名字，写了两次，就有两处需要分别检查。

```rust
let x = 4;
let y = x + x;
```

第二行的两个 `x` 各有一个节点编号，后面可以分别记录它们的类型和用途。它们是否指向同一个声明，要等名字查找完成。源码范围通常记成 `[开始, 结束)`：包含开始位置，不包含结束位置。若一个词占用偏移 8 到 10，范围就写成 `[8, 11)`。

给 `f(x)[i]` 标位置时，范围从 `f` 扩展到最后的右方括号。到文件末尾还要处理结束标记；空文件也应有合理的位置，不能凭空取第一个声明。

编号和位置回答“出现在哪里”，名字和原文则帮助回答“当时写了什么”。像整数后缀这样的细节，也需要继续留下来。

```rust
let mask: u32 = 0xffu32;
```

`mask` 用于后面的名字查找；`0xffu32` 同时包含十六进制写法和 `u32` 后缀，后面解析数值与类型时都用得上。即使最初读取字符和 `token` 的临时对象已经结束使用，AST 仍然要能说明这个整数写了什么、出现在哪里。整个文件的范围可以从第一个声明延伸到最后一个声明。文件为空时，则保留空输入的位置。这样读树和报告错误都不会依赖已经结束的临时数据。

## 规则与词

沿 CST 往下读时，会遇到两类内容：**规则节点**保存一段语法的内部结构，**终结符**已经对应到具体的词。两者需要不同的读法。

```rust
a + b * c
```

加法这一层可以看到左表达式 `a`、加号，以及右表达式 `b * c`。加号已经是一个直接可读的词，乘法还需要继续进入内部。如果把每个孩子都当作操作符，就会漏掉子表达式；如果把加号也当作需要不断展开的规则，也找不到更深的结构。实际读取时先判断孩子属于哪一类，再决定是取出词的内容，还是递归读它的孩子。

不过，操作符在 CST 中出现的层次，也和文法怎么写有关。同一个加号可以直接出现，也可以包在一层命名规则里。

```antlr
sum : value ('+' value)* ;
// 也可以把操作符单独命名：
addOp : '+' | '-' ;
```

第一种组织中，加号直接出现在表达式的孩子里。第二种组织中，外层可能先看到 `addOp`，再进入里面取得加号或减号。两种包装都能表示相同的加法。建立 AST 时，应留下操作符与左右表达式，而无须把每一层文法包装都保存成操作。普通表达式、条件表达式和语句位置的表达式也可能使用不同规则名。名字帮助选择读法，最终仍要落实到相应的程序结构。

把这些层次整理成 AST 后，还能打印出来核对。遇到程序错误时，则需要另外说明出错的位置和原因。

```rust
fn main() {
    let y = missing + 1;
}
```

树中能看到加法，左边是名字 `missing`，右边是整数 1。名字查找发现 `missing` 没有可见声明，于是记下错误。显示消息时可以指出第二行中 `missing` 的范围，并说明“找不到名字”。这与把加法节点打印出来是两种用途。错误与警告也要区分：错误表示当前程序有无法正常通过的部分；警告用来提醒值得检查的写法。收集时留下类别、消息和位置，最后就能统一显示。
