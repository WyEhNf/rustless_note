## 路径与名字位置

`Path` 保存名字及其分段。`Point` 是单段路径，`Point::get` 有两段。建树时保留这些名字和分段关系，使用时再结合它出现的位置确定查找对象。

```rust
struct Point { x: i32 }
impl Point { fn get(&self) -> i32 { self.x } }
fn main() {
    let p: Point = Point { x: 1 };
    let n = Point::get(&p);
    let x = p.x;
}
```

冒号后的 `Point` 写在类型位置，用来说明 `p` 的类型；构造式开头的 `Point` 指定要构造的结构体。`Point::get` 通过所属类型找到关联函数。`p.x` 则先使用局部值 `p`，再访问它的字段。

两种成员写法因此保留不同结构：关联路径带着 `Point` 与 `get` 两个名字，字段访问带着接收者表达式 `p` 与字段名 `x`。接收者还可以是更复杂的表达式，例如 `make_point().x`，此时需要先得到函数调用的结果。

## 名字与构造

路径也可以使用一个已经构造好的数组或结构体。名字本身无需重新带上这个值的全部组成。

```rust
struct Point { x: i32 }
fn main() {
    let a = [1, 2];
    let p = Point { x: 3 };
    let b = a;
    let n = p.x;
}
```

`[1, 2]` 的孩子是两个元素，`Point { x: 3 }` 保存字段名与初值。后面再次写 `a` 或 `p`，只出现名字使用，语义分析通过作用域找到先前的绑定。路径能找到声明，继而取得类型；值最终放在哪个寄存器或地址，还要由更后的处理确定。

**构造式保存组成内容，路径让已经声明的内容能够再次被使用。**

## 类型实参与值实参

路径中还可能带有类型信息。容器写法能说明类型实参与普通调用实参的区别。

```rust
fn add(x: i32) -> i32 { x + 1 }
fn main() {
    let n = add(3);
    let values: Vec<i32> = Vec::<i32>::new();
}
```

`add` 声明中的 `x` 是值参数，调用时的 3 是值实参。`Vec<i32>` 中的 `i32` 是类型实参，规定容器的元素类型。表达式位置写作 `Vec::<i32>::new()` 时，也要把 `i32` 留在路径的相应部分；末尾括号里则没有值实参。

类型实参本身仍可嵌套，例如 `Vec<[i32; 3]>` 的实参是一整个数组类型。保留路径段还不够，里面的类型也需要递归读取。当前 `Box`、`Vec` 有专门的类型实参规则，普通用户函数和结构体尚未具备通用类型参数支持。

## 声明上的参数名

声明有时还写着生命周期参数名。下面只观察语法信息，引用有效期的完整检查超出本文范围。

```rust
fn first<'a>(x: &'a i32) -> &'a i32 { x }
```

`'a` 在声明处起名，在参数引用和返回引用处表达联系。仅保留声明中的这个名字，还无法确定所有引用可以使用多久；各使用处的关系也需要被保存和检查。当前范围只记下一部分参数名。

通用类型参数、常量参数和 `where` 约束也需要专门的语法内容与检查规则。这里读路径时，只把已经出现的名字、分段和类型实参保留下来，后续声明解析再判断这些写法是否受支持。
