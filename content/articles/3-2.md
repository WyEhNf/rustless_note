## Path：名字与分段

路径保存名字及其分段，例如 `Point::get`。同一个名字出现在**类型位置和表达式位置**时，查找的目标可能不同；点号访问字段又是另一种情况。

```rust
let p: Point = Point { x: 1 };
let n = p.x;
```

冒号后面的 `Point` 要找到一个类型。等号右边的 `Point` 用来选择要构造的结构体。第二行中的 `p` 是局部值，`x` 是这个值所属结构体的字段。`Point::get` 则把名字写成多个段，表示到 `Point` 下查找 get。字段访问的点号与这种关联路径需要分开理解。路径保存的是名字及其层次。变量最后放在哪个寄存器或内存地址，要到更后的阶段才决定。

路径找到的值还可以是数组或结构体。这里容易混淆的是：构造这些值需要元素或字段，使用它们的名字则需要查找声明。

```rust
let a = [1, 2];
let p = Point { x: 3 };
let n = p.x;
```

`a` 保存一个数组，`p` 保存一个结构体。再次写 `a` 或 `p` 时，出现的是名字使用，后面通过作用域找到先前的绑定。`[1, 2]` 的孩子是两个元素值，`Point { x: 3 }` 的孩子包含字段值，`Point::get` 的各段则是查找用的名字。名字可以绑定计算结果、数组、结构体或其他值。路径的作用是找到声明，再由声明获得类型和意义。

完整 `Rust` 中，类型名字还可以来自别名。把这一种情况放进来，能进一步看清名字和它所代表的类型之间的关系。

```rust
// 完整 Rust 的例子
 type Count = u32;
 let n: Count = 3;
 let bad: Count = true; // 错误：需要 u32
```

`Count` 指向 `u32`，因此 `n` 的要求与写成 `u32` 相同。`bad` 的初值是 `bool`，换了类型名字也无法满足整数要求。这个例子说明路径还可以找到类型别名。要支持它，语言需要有 `type` 声明，并让类型查找能够处理别名。当前讨论的子集没有 `type` 声明，这里保留为扩展认识。

## 参数与约束

写函数调用时会传入值，写 `Vec<i32>` 时则给出了元素类型。它们都常被叫作“参数”，阅读时最好先分清声明中的**参数和使用处给出的实参**。

```rust
fn add(x: i32) -> i32 { x + 1 }
let n = add(3);
let values = Vec::<i32>::new();
```

`add` 声明中的 `x` 是值参数，调用里的 3 是值实参。`Vec` 使用 `i32` 作为类型实参，说明元素类型。类型位置可以写 `Vec<i32>`，表达式中的关联调用常写成 `Vec::<i32>::new()`。

两处都需要留下 `i32` 这个类型信息。生命周期参数如 `'a` 也是编译期信息。当前保存范围偏重生命周期参数名和使用处的类型实参，用户定义的通用类型参数还未完整支持。

### 生命周期参数

生命周期名字也是编译期信息，不过，留下一个名字还不足以说明引用之间的全部关系。

```rust
fn first<'a>(x: &'a i32) -> &'a i32 {
    x
}
```

这里 `'a` 同时出现在参数引用和返回引用上，说明返回引用的有效期与输入有联系。若只知道函数声明写了一个名为 `'a` 的参数，却没有完整保存每处引用上的关系，就无法据此完成有效期推导。当前范围会记下一些生命周期参数名，但没有完整的生命周期与 `where` 约束检查。阅读后面的引用例子时，还要把类型、写权限与引用有效期分开看。

### 泛型与 where 约束

通用泛型还会遇到 `where`。它给类型参数补上约束，让函数体能够依据这些要求使用传入的值。

```rust
// 完整 Rust 的例子
fn duplicate<T>(x: T) -> (T, T)
where T: Clone {
    (x.clone(), x)
}
```

`T` 是类型参数；`Clone` 表示能够克隆一个值。约束告诉检查器，函数体中可以调用 `x.clone`()，再把克隆值和原值组成元组。删掉约束后，任意 `T` 都能传入，而任意类型未必支持 `clone`，函数体就缺少依据。完整模型可以分别表示类型参数 `T`、生命周期参数 `'a` 和常量参数 `const N`，再把约束挂到声明上。这里的用户泛型、元组和通用约束属于扩展内容。
