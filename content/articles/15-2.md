## 字段权限

字段访问从接收者类型出发，查找这个结构体有没有相应字段。查到之后，字段类型和字段声明身份都会成为本次表达式的结果信息。

```rust
struct Point { x: i32 }
let p = Point { x: 1 };
let a = p.x;
let b = p.y; // 错误：没有 y 字段
```

`p` 的路径查找先确定局部绑定属于 `Point`，`.x` 再从 `Point` 中找到字段声明及 `i32` 类型。`y` 则没有对应字段。接收者若包在引用或 `Box` 里，可以按规则自动解开，并保留动作与权限。结果还记录字段身份，而不只保存文字 `x`。接收者也可以来自函数，例如 `make_point().x`。名字查找只是取得接收者的一种方式。

字段访问把[位置与权限规则](/posts/13.1)应用到结构体内部。字段存在以后，还要把接收者沿途的限制传给字段结果。

```rust
let mut p = Point { x: 1 };
let r = &p;
let n = r.x;
r.x = 2; // 错误
```

`p` 本身是可变绑定，但 `r` 提供共享引用。读取 `x` 可以成立，经 `r` 写入则被限制。自动解引用进入 `Point` 时，需要把这项限制继续传给字段结果。否则只查看原始 `p` 的 `mut`，就会漏掉 `r` 这一访问步骤。因此写权限属于当前访问路径，不能仅从最初对象的声明推断。

反过来，引用变量本身没有 `mut`，并不一定阻止修改字段。它所保存的引用类型也会影响对目标的访问权限。

```rust
let mut p = Point { x: 1 };
let r = &mut p;
r.x = 2;
```

`r` 的绑定不能随意改成另一个引用，但它持有 `&mut Point`。沿这一层引用进入 `Point` 时，可以得到可写访问，于是 `x` 可以修改。如果外面再包一层共享引用，情况就会改变。已有共享访问限制会保留，不能被内部 `mut` 清除。这个例子只涉及访问路径权限。多个引用是否同时存在、何时结束，还需要完整借用规则继续处理。

再把可变引用放进字段里面，访问链就更长了。外层已经留下的共享限制，仍然要继续传到最后一步。

```rust
// 引用关系示意；这里只分析字段访问，暂不检查生命周期。
struct Holder<'a> { value: &'a mut i32 }
let mut n = 1;
let h = Holder { value: &mut n };
let s = &h;
*s.value = 2; // 访问经过共享引用
```

通过 `s` 找到 `Holder` 时已经是共享访问。取出 `value` 字段后，字段类型虽然是可变引用，受限来源仍然存在。因此最后的星号不能重新打开写权限。`&&mut Point` 也是同样道理：先遇到共享层，再遇到可变层，限制继续保留。每一步都传递访问结论，才能覆盖字段与解引用交替出现的长链。

**字段类型要继续传递，访问途中留下的限制也要继续传递。**

## 元素权限

下标访问要同时检查容器和索引。容器决定元素类型，索引按 `usize` 检查，得到的元素位置再参与后续读取或修改。

```rust
let mut a = [10, 20];
a[0] = 30;
a[1usize] = 40;
let i: i32 = 0;
let x = a[i]; // 当前规则下类型不匹配
```

无后缀的 0 可以从下标位置得到 `usize`，`1usize` 明确符合要求。`i` 已经是 `i32`，不会只因它等于 0 就自动改类型。接收者还可以经过引用或 `Box` 到达数组或 `Vec`。下标结果得到元素类型，并作为元素位置参与后续操作。类型与权限通过以后，索引是否越界还需要后面的执行规则处理。这里不能据此保证任意 `usize` 都在范围内。

同一个数组，经不同引用访问会得到不同的写权限。索引类型完全正确，也不一定能写入选中的元素。

```rust
let mut a = [1, 2];
let r = &mut a;
r[0] = 3;
let s = &r;
s[0] = 4; // 错误：外层共享访问
```

`r` 提供 `&mut [i32; 2]`，因此选中的元素可以写。`s` 又增加外层共享引用，访问元素时受到限制。索引本身都可以按 `usize` 检查，失败原因在**接收者访问路径**。仅看数组原来用 `let mut` 声明，无法区分这两次使用。字段访问与下标访问都需要逐层传播这种权限，而不能在找到最终类型后把沿途信息丢掉。

`Vec` 元素本身又是可变引用时，还会出现类似的多层访问。下标这一步留下的限制，需要传给后续解引用和调用。

```rust
let mut x = 1;
let mut v = Vec::<&mut i32>::new();
v.push(&mut x);
let shared = &v;
*shared[0usize] = 2; // 错误
```

`shared` 只允许共享访问 `Vec`。下标得到的元素类型虽然是 `&mut i32`，仍要保留这次取元素的限制。后面的星号读取这个限制，因此不能修改 `x`。把下标结果传给要求可变引用的调用时，也应继续检查受限来源。这里是当前访问路径的规则，不能代替完整生命周期与多个借用之间的冲突检查。

## 连续访问

一串点号和括号读起来很紧凑，AST 中却有多个相互嵌套的表达式。分别检查它们，才能说明哪一步在找字段、哪一步在传方法接收者。

```rust
struct Bag { values: Vec<i32> }
let bag = Bag { values: Vec::<i32>::new() };
let p = &bag;
let n = p.values.len();
```

先检查字段访问：沿 `p` 的共享引用找到 `Bag`，再取得 `values`，结果保留共享限制。然后检查 `len`：按只读接收者要求使用这个 `Vec`。字段的解引用用于找到字段位置，方法的借用用于传递接收者。两组结论**分别属于各自节点**。若把 `len` 换成 `push`，就需要可写接收者，先前传下来的共享限制会阻止修改。
