## 当前范围与扩展能力

这一章把前面的认识向外扩展，同时回看哪些概括需要带上条件。AST 可以保存更多语法结构，语义分析也可以处理更复杂的类型和约束；这些能力各自需要相应信息，不能仅由某个相似写法已经出现就推断完成。

前面的 `let` 主要绑定一个名字，`Type` 主要讨论 `Unit`、路径、引用和数组。完整 `Rust` 还包含模式、元组、切片、函数指针和更多类型形式。模式说明怎样从一个值里拆出需要的部分，`if` `let` 与 `match` 也会用到它。

```rust
// 完整 Rust 的例子
let (x, y) = (1, 2);
fn duplicate<T: Clone>(value: T) -> (T, T) {
    (value.clone(), value)
}
```

第一行的左边有一个元组模式，需要描述两个名字分别取哪一部分。函数中的 `T` 是类型参数，`Clone` 约束让函数体可以克隆 `value`。后面可以按具体类型生成不同版本，也可以在其他语言规则下考虑共用代码；类型检查和最终生成方式还需要分别安排。

## 引用有效期与借用冲突

名字在作用域里可见，说明现在能够找到这个绑定。引用是否有效，还要知道它指向的目标能存在多久。一个外层引用如果指向已经退出内层范围的值，就会有悬垂问题。

```rust
// 用于说明完整借用检查需要处理的冲突
let mut x = 1;
let a = &mut x;
let b = &mut x;
*a += 1;
*b += 1;
```

单看创建引用时，`x` 是可写位置；把后续使用放在一起看，两个可变借用却指向同一对象并发生冲突。移动后的再次使用、内部可变性的专门规则，也都需要更多分析。当前类型和访问权限检查只能说明其中一部分。

栈、堆与逃逸分析则继续涉及运行时存储。编译器保存 AST 的对象和目标程序运行时的对象处于不同层次，解释它们时要分清讨论的是谁。

## 表示共享与结果复用

重复名字可以共用文本，重复类型可以共用规范表示，但同名声明仍需不同身份，否则局部遮蔽就会被混淆。检查结果也可以考虑缓存，前提是知道它依赖哪些内容，以及源码改变后哪些结论仍然有效。

例如函数只改了内部运算，签名要求可能继续适用；返回类型改变后，相关调用就可能要重新检查。通用模块、导入别名、可见性和泛型方法查找又会增加更多依赖。正文把这些可能的扩展与当前完整重查的方式分别说明。

## 概念关系与适用范围

**扩展一种语法或能力时，要同时说明它需要保存什么，以及后面依据什么作判断。**

本章把更多类型、泛型和引用检查放在一起，接着讨论信息复用与更完整的查找，最后回看 `Primary` 与叶子、声明身份与节点编号、`expected` 与实际推导等容易混淆的关系。末尾还说明原对话中的矩阵乘法讨论为何单列附录，让 AST 主线与额外话题各自保持清楚。
