## 接收者调整

方法调用先检查点号前面的接收者。它可能套着引用或 `Box`，需要逐层找到用于查方法的基础类型，同时保留这一路的访问方式。

```rust
struct Point { x: i32 }
impl Point { fn get(&self) -> i32 { self.x } }
fn main() {
    let b = Box::<Point>::new(Point { x: 1 });
    let r = &b;
    let x = r.get();
}
```

`r` 是 `&Box<Point>`。先沿引用得到 `Box<Point>`，再沿 `Box` 得到 `Point`，随后到 `Point` 的关联成员中找 `get`。接收者可以是变量，也可以是更复杂表达式。每次自动解引用都要保留发生顺序和得到的类型。这一步只是找方法的依据。方法最终需要共享借用、可变借用还是按值接收，还要**等签名确定**。

如果给上面的 `Point` 增加 `set` 方法，两种签名就会提出不同的接收者要求。下面展示这两个方法，并分别调用。

```rust
// 替换前例的 impl；其余片段放在 main 中。
impl Point {
    fn get(&self) -> i32 { self.x }
    fn set(&mut self, x: i32) { self.x = x; }
}
let mut p = Point { x: 1 };
p.get();
p.set(2);
```

`get` 需要 `&Point`，`set` 需要 `&mut Point`。因此同一个 `p`，在两次调用中补上的借用形式不同。如果接收者先经过引用或 `Box`，还要先记录解引用，再追加对应借用。按值 `self` 则没有这一额外借用步骤。`set` 还要求访问路径可写。知道应该补可变借用，并不意味着权限一定允许。

这些接收者调整和整个调用的结果还要分别记录。开头的 `r.get()` 把 `&Box<Point>` 逐层调整为方法所需的 `&Point`，调用整体仍按签名得到 `i32`。

调用记录因而同时保留 `Point::get` 这个目标、方法声明身份、结果类型，以及接收者的解引用和借用步骤。找到并借用 `Point` 说明怎样传入对象，方法签名另外说明调用返回什么。

## 方法的范围

内建容器方法按专门规则处理。它们支持哪些操作，也支持哪些接收者形状，都需要逐项看清楚。

```rust
let mut v = Vec::<i32>::new();
v.push(1);
let n = v.len();
let empty = v.is_empty();
let x = v.remove(0usize);
let copied = v.clone();
```

`push` 与 `remove` 要求可写 `Vec`，分别返回 `Unit` 和元素；`len` 返回 `usize`，`is_empty` 返回 `bool`，`clone` 还检查 `Clone` 能力。数组也可使用这里的 `len` 与 `is_empty`。

当前 `len`、`is_empty` 的接收范围主要是直接数组或 `Vec`，以及一层引用。`push`、`remove` 也只在专门分支中剥去一层引用。

所以不能看到前面存在多层解引用，就推断 `Box` 或任意多层引用包着容器时，这些方法都同样可用。

用户结构体则根据所属类型查关联成员。查到一个关联函数之后，还要确认它**是否带 `self`**，才能决定能否用点号调用。

```rust
impl Point {
    fn new() -> Point { Point { x: 0 } }
    fn set(&mut self, x: i32) { self.x = x; }
}
let mut p = Point::new();
p.set(2);
p.new(); // 错误：new 没有 self
```

`new` 不需要已有 `Point`，所以使用 `Point::new`。`set` 操作已有对象，接收者 `p` 必须可写，显式参数 2 再按 `i32` 检查。用户方法按基础结构体与方法名找到声明，然后检查 `self`、参数数量和类型。

当前方法实参检查与普通调用在权限判断上仍有差别：方法路径缺少普通签名检查中的一项可变引用来源限制。不能把接受结果扩大成完整借用安全保证。


这里讨论的查找范围由内建分支和用户结构体关联成员构成。切片、整数方法、泛型约束等需要其他类型信息与规则，不能由这套关联表直接推出。
