## 类型中的层次

字段、参数、返回值和局部标注都可以写类型。类型又能由类型组成：引用带着所指类型，容器带着元素类型，数组还带着长度。因此读完声明名字后，往往还需要进入一棵类型子树。

```rust
const N: usize = 3;
fn use_rows(rows: &mut Vec<[i32; N]>) {}
```

`rows` 的最外层是可变引用，引用目标是 `Vec`，容器的元素是固定长度数组，数组元素才是 `i32`。每一层都有自己的内容。只保留最里面的整数，会丢掉容器与访问方式；只保留最外面的引用，又无法知道它所指对象的组成。

数组长度写成 `N` 时，建树可以先留下这个名字。`usize` 是长度等位置使用的无符号整数类型，声明给出了常量的类型，但数组究竟多长，仍要在语义分析中找到 `N` 并取得值 3。

## 路径出现的位置

类型里的名字与表达式里的名字可以采用相近写法。一个路径应当找到什么，要结合它在程序中的位置理解。

```rust
struct Point { x: i32 }
fn main() {
    let p: Point = Point { x: 1 };
    let n = p.x;
}
```

标注中的 `Point` 需要一个类型，构造式开头的 `Point` 选择结构体，`p.x` 则通过已有对象取得字段。路径先保留名字与分段；字段访问还要保留接收者表达式。这样语义分析能够分别检查类型查找、构造和字段使用。

`Point::read` 一类关联路径还带有所属类型。它与 `p.read()` 的结构不同：前者把类型和成员写成路径，后者把一个值作为方法接收者。AST 需要保留这些差异，后面才能采用相应查找方式。

## 写法与确定含义

`Vec<i32>` 中的 `i32` 是类型实参，说明容器装什么；`f(3)` 中的 3 是值实参，说明这次调用传入什么。类型实参内部又可以是数组或引用，因而仍要递归读取。

源码中的 `Type` 保存这种写法，语义类型则保存名字与长度已经确定后的含义。两个位置分别写 `[i32; N]` 和 `[i32; 3]`，会产生不同语法节点；当 `N` 求得 3 后，它们可以代表相同类型。相反，同样写成数组，元素或长度不同就仍然是不同类型。

**类型子树留下每一层写法，名字与长度解析完成后，才有完整的类型可供比较。**

声明上的参数名也属于需要保留的信息，但语法上记下一个名字，还需要对应的规则来解释它。本文以当前支持的类型和容器实参为主，在相关位置说明保存写法与完成检查的范围。
