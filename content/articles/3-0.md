## 类型的嵌套层次

这一章主要讨论两件相连的事：类型写法怎样形成子树，以及类型里的名字怎样得到确定含义。声明写了一个类型，并不代表只保存一个类别就够了，引用、数组和容器都还带着内部信息。

```rust
const N: usize = 3;
let rows: &mut Vec<[i32; N]>;
```

这里只观察类型写法。最外层是可变引用，它指向 `Vec`；`Vec` 的元素是固定长度数组；数组元素是 `i32`，长度写成 `N`。读这个类型时要逐层进入，外层是否可变、容器装什么、数组多长，都有自己的意义。`usize` 是用于长度等位置的无符号整数类型。

建树阶段可以先保存 `N` 这个名字。语义分析找到对应常量并求出 3 之后，数组长度才确定下来。源码中的 `Type` 保存写法，解析后的语义类型保存已经确定的含义，后面比较类型时会使用这些结果。

## 名字与声明

路径保存名字及其层次，例如 `Point::read`。其中 `Point` 和 `read` 是不同的段，双冒号说明后一个名字与前面的类型有关。类型位置写 `Point`，是要求找到一个类型；表达式位置写 `p`，则可能找到局部绑定；`p.x` 还要先得到 `p` 的类型，再查字段 `x`。

```rust
struct Point { x: i32 }
let p: Point = Point { x: 1 };
let n = p.x;
```

第一处 `Point` 规定 `p` 的类型，第二处 `Point` 选择要构造的结构体，`n` 的初值则读取这个值的字段。同样的名字或相近的写法，要结合出现位置理解。路径最终关联到声明，值运行时放在哪里还属于后面的工作。

## 参数与约束

类型里还能出现编译期参数。`Vec<i32>` 中的 `i32` 是类型实参，说明元素类型；函数调用里的 `f(3)` 则传入值实参。声明处为将来传入内容起的名字叫参数，使用处真正给出的内容叫实参。

完整 Rust 的泛型还可以声明类型参数 `T`，并用 `T: Clone` 这样的约束说明它具备什么能力。生命周期名字如 `'a` 则用来表达引用有效期之间的关系。留下参数名字只是起点，完整检查还要把各处使用和约束联系起来。

当前讨论保存一部分生命周期参数名，并为 `Box`、`Vec` 的类型实参提供专门规则。通用类型别名、用户类型泛型和完整 `where` 约束仍放在扩展范围中，正文会结合例子说明它们需要补充什么。

## 类型与编译期信息

**先按层次读出类型，再解释其中的名字和参数，才能得到可比较的完整类型。**

两个数组都属于数组，但元素类型或长度不同，就可能无法相互使用。两个位置写了不同的常量名字，求值后也可能得到相同长度。本章把类型结构、路径查找和编译期信息放在一起讲，后面进入声明解析和表达式检查时，就能说明每一条类型要求来自哪里。
