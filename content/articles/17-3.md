## 结构、查找与类型规则

读完主线后，可以用几组小例子重新核对概念。先看 AST：文法中的包装、树中的孩子和名字的含义，需要分别理解。

```rust
let x = 1;
let y = (x + 2) * 3;
```

`Parser` 先组织语法规则，之后再整理成 AST。括号加法可以作为乘法起点，但内部仍有 `x` 与 2，说明 `Primary` 不一定是叶子。`x` 在这里是名字使用，后面绑定到声明，不能直接把路径当作寄存器。`let` 的初值、块的语句和操作数也通过不同形式连接。

尾值可以按位置和分号识别，无须独立节点类别。保存 `use` 文本或生命周期参数名，也只说明相应写法被记下，还需额外规则支持完整查找与约束。

再看语义分析。局部查找时使用的表，与之后继续保存的节点结果，保留时间和用途都不同。

```rust
const N: usize = 3;
let x = 1;
{
    let x = true;
    let y = x;
}
```

两个 `x` 是不同声明，`y` 的使用点按自己的节点身份关联内层 `x`。离开块后局部查找层消失，已经确认的关系仍然保留。字面量与加法等节点不必各自成为新符号。常量 `N` 的类型与值又是另外的记录；允许引用 `N`，不代表常量 `N + 1` 已受支持。

有限布局只说明直接包含能否结束，`Copy` 要按字段规则判断，`Clone` 怎样复制也依类型而定。类型解析结果有记录，还需要实际查询与复用步骤才能称为缓存。

最后回到表达式。很多简短的概括能帮助入门，但**具体到当前规则**时，还要看表达式形式和使用位置。

```rust
let a: u32 = 1;
let b: u32 = 1 + 2; // 当前二元规则下不能同样推导
let c: u32 = if flag { 1 } else { 2 };
```

`a` 和 `c` 能把 `u32` 期望传到字面量，`b` 的左侧却先独立推导。这说明 `expected` 没有统一穿透所有孩子。隐式调整可以保存到独立记录，无须立即改写 AST；错误也可能由具体 `let` 或调用位置报告。整数范围、`loop` 首个 `Never`、早期跳转后的不可达内容都有当前限制。

普通调用与方法调用、显式 `clone` 与点 `clone`、不同内建接收者包裹层，也各有检查差别。前面相应小节用正反例展开，不能由其中一条成功路径推断全部情况。

## 附录的由来

原始对话除了 AST 和语义分析，还讨论过一段矩阵乘法。它的重点在计算与访问方式，这里用一个点积片段说明后面附录从哪里开始。

```cpp
for (int k = 0; k < n; ++k) {
    sum += a[i * n + k] * b[k * n + j];
}
```

固定 `i` 与 `j`，这个循环把 `A` 的一行与 `B` 的一列逐项相乘再相加，得到结果矩阵的一项。原题固定 `n`=1024，讨论了转置、分块、AVX2、循环展开与对齐，后续还要求去掉注释。附录按这些想法给独立小例子，并保留原讨论的限制与需要更正之处。原始完整回答继续留在本地资料中。
