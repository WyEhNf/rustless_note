## 类型与值

常量有声明类型，也有编译期算出的值。这两项需要分别处理：读懂类型不保证初值符合要求，知道一个数字也还需要知道它按什么类型解释。

```rust
const N: usize = 3;
const BAD: bool = 3; // 错误：初值类型不合适
```

`N` 的声明类型是 `usize`，求初值后得到 3。`BAD` 虽然能读出声明类型 `bool`，初值却不能按 `bool` 使用。两项处理可以各自记下尚未开始、正在处理、完成或失败。这样重复请求时可以复用完成结果，也可以识别再次进入当前处理链的情况。把值提前算出来叫编译期求值。它只处理当前支持的表达式范围。

当初值引用另一个常量时，求值就要顺着这条依赖继续向下。名字的绑定关系也在这里确定。

```rust
const A: usize = B;
const B: usize = 3;
fn main() { let data: [i32; A] = [0; A]; }
```

求 `A` 时先看到 `B`，继续求 `B` 得到 3，于是 `A` 也得到 3。数组类型与重复次数都可以使用这个结果。初值中的 `B` 还要记下关联的是哪条常量声明，这样类型和值都有明确来源。没有被函数使用的常量也应检查。只检查“碰巧用到”的常量，会让未使用声明中的错误悄悄留下来。

这种求值并不总能等所有类型都处理完再开始。数组长度就可能让类型解析提前请求某个常量的值。

```rust
const N: usize = 3;
struct Row { values: [i32; N] }
```

读 `Row` 的字段时，仅知道 `N` 的类型是 `usize` 还不够。为了确定完整数组类型，还需要知道它的值为 3。因此可以在解析字段类型的过程中请求 `N` 的值，然后再回来完成数组类型。若强行规定所有类型必须完全结束后才允许求任何值，这个例子就无法向前。分开记录类型进度与值进度，可以知道究竟卡在哪一项依赖上。

**类型和值分开记录进度，也允许在有依赖时相互配合。**

## 循环依赖

沿常量依赖往下走时，可以记下每个常量尚未开始、正在处理、已完成或已失败。再次遇到一个名字，要结合这个状态判断发生了什么。

```rust
const A: usize = B;
const B: usize = A;
```

进入 `A` 时记为正在求值，接着进入 `B`，再次请求 `A` 时，它仍在**当前链上**，于是发现环。这种先沿一条链走到底的方法叫深度优先搜索，简称 DFS。处理完成后再回到上一层。若 `B` 已经独立算完，多个常量都引用它，则可以直接复用结果。重复使用一个已完成的常量，不会自动构成依赖环。

依赖还可能穿过类型中的数组长度。这样，即使单看初值没有明显的引用环，处理类型时也可能回到尚未完成的起点。

```rust
// 非法例子，用来观察依赖
const A: [i32; B] = 0;
const B: [i32; A] = 0;
```

解析 `A` 的类型需要 `B` 的值；使用 `B` 前又进入 `B` 的类型，后者继续需要 `A`。再次进入尚未完成的 `A`，就发现类型处理链成环。这个例子还包含其他错误：长度应为 `usize`，数组声明的初值也不能直接是 0。这里专门观察的是为何仅检查值依赖还不够。类型进度和值进度分开记录，可以分别识别这两种返回起点的情况。

发现环以后，已经留下的临时数据需要结合失败状态理解。继续查看其他错误，不会改变这个常量已经无法正常求出的事实。

```rust
const A: usize = B;
const B: usize = A;
fn main() { let x = A; }
```

`A` 与 `B` 的环已经说明它们不能正常求值。即使后续处理留下临时数值或状态，`x` 也不能据此被当成合法常量使用。当前讨论中，类型失败状态会避免被递归返回覆盖；值求解的失败路径并不完全相同，需要特别保留这个差别。最终判断能否继续生成正常程序，要看是否已经存在错误。失败记录的意义是防止重复处理，也方便继续发现独立问题。
