## 函数与调用目标

看到一对调用括号，还要先判断前面的表达式表示什么。只有它能提供可调用的目标，后面的参数检查才有依据。

```rust
fn add(x: i32) -> i32 { x + 1 }
add(2);
let n = 3;
n(); // 错误：整数没有函数类型
```

`add` 的名字找到函数声明，因此可以继续取得签名。`n` 是局部整数，括号无法改变它的类型。调用结构先保存被调用者，再按顺序保存实参。实参本身可以是任意受支持的表达式，需要继续递归检查。被调用者出错后，仍可以检查已有实参里的独立问题；这不会让当前调用变得合法。

确定它指向函数以后，就能根据声明身份找到完整签名。同属函数类型，并不表示参数要求也相同。

```rust
fn positive(x: i32) -> bool { x > 0 }
let flag = positive(3);
```

名字 `positive` 指向确定的函数声明。根据它的记录，调用得知需要一个 `i32`，正常结果为 `bool`。函数类型描述可以先保存函数名字或身份，完整参数列表则留在声明记录中。调用时继续查到签名即可。因此看见“函数类型”这个类别，还不能只凭类别猜参数。不同函数都可调用，却有各自不同的输入输出要求。

调用检查完时，**结果类型和调用目标**都需要留下。两个调用即使返回同一种类型，执行的函数也可能不同。

```rust
fn one() -> i32 { 1 }
fn two() -> i32 { 2 }
let a = one();
let b = two();
```

`a` 和 `b` 的初值都得到 `i32`，但分别调用 `one` 和 `two`。若只保存结果类型，就无法恢复实际要执行哪一个函数。关联调用还需要完整目标，例如 `Point::get`，以及对应声明身份。不同调用检查分支结束时，可以统一补齐这些结论。对话中提到用闭包收集这些结果。闭包就是一段可调用的代码连同它使用的外部信息；这里需要理解的重点是最终信息要完整。

## 实参与签名要求

签名给出了每个参数的位置和类型。调用先核对数量，即使数量有误，也仍可以继续查看各个实参中的独立问题。

```rust
fn f(x: i32) {}
fn main() { f(true, missing); }
```

`f` 只需要一个参数，调用却给出两个。第一个参数 `true` 还能与 `i32` 比较，发现类型错误；第二个 `missing` 没有对应参数期望，但仍可做名字查找。于是同一次检查可以说明数量错误、首参类型错误和 `missing` 未定义。继续检查只用于提供更多信息。不能因为走完了所有参数，就忽略最初已经发现的数量问题。

数量合适时，每个实参再取得**自己对应的 `expected`**。换一下位置，就可能违反不同的参数要求。

```rust
fn f(n: usize, flag: bool) {}
f(3, true);
f(true, 3); // 两个位置都不合适
```

第一次调用让 3 按 `usize` 检查，`true` 按 `bool` 检查。交换位置后，两项要求都无法满足。若要求引用，还要检查是否存在允许的适配。要求可变引用时，受共享访问限制的来源也不能被忽略。调用可以看成多个输入共同得到一个结果的操作，不过它还需要先找到函数、读取签名，并区分普通函数、方法和内建内容。

带 `self` 的方法还多了一个接收者。点语法把它写在点号前，显式关联调用则需要把它放进实参列表。

```rust
struct Point { x: i32 }
impl Point { fn get(&self) -> i32 { self.x } }
let p = Point { x: 1 };
let a = p.get();
let b = Point::get(&p);
```

`get` 声明要求共享接收者。点语法可以根据签名补上借用，显式关联调用则把 `&p` 放在前面。方法记录的普通参数列表可以不包含 `self`；真正检查显式调用时，再把接收者要求放到列表最前面。若写 `Point::get()` 就缺少接收者；若给出错误类型，同样要按签名报告不匹配。
