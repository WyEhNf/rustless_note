## 类型与泛型

前面的讨论集中在一组受限语法。完整 `Rust` 还包含模式、更多类型和泛型约束；加入这些写法时，树中也需要有地方表达它们。

```rust
// 以下都是完整 Rust 的扩展例子
let (x, _) = (1, true);
let [a, b] = [1, 2];
let Point { x: renamed } = Point { x: 3 };
enum Answer { Number(i32), Flag(bool) }
let v = if flag { Answer::Number(1) } else { Answer::Flag(true) };
let slice: &[i32] = &[1, 2];
let f: fn(i32) -> i32 = inc;
let n: _ = 1;
```

前三行分别演示元组拆分、数组拆分、字段重命名，`_` 表示忽略一部分。这些都需要 `Pattern`；`if` `let` 与 `match` 也按模式选择或绑定。`Answer` 把不同内容放进同一种枚举，所以 `if` 两支整体同为 `Answer`。切片描述连续元素的访问视图，函数指针表示可调用值，类型位置的 `_` 请求推导，`!` 可以显式写 `Never` 类型。

`Trait` 规定能力；trait object 通过共同能力访问不同具体类型。当前四类 AST 类型和单名字 `let`，还需要扩展才能完整支持这些写法。

泛型进一步提出了两个问题：怎样根据约束检查函数体，以及后面怎样处理不同类型的调用。这两步可以分别考虑。

```rust
// 完整 Rust 的例子
fn copy_value<T: Clone>(x: T) -> T { x.clone() }
let a = copy_value(1i32);
let b = copy_value(true);
fn shorten<'a: 'b, 'b>(x: &'a i32) -> &'b i32 { x }
fn first<const N: usize>(a: [i32; N]) -> i32 { a[0] }
```

`T` 需要支持 `Clone`，两个调用分别代入 `i32` 和 `bool`。若分别生成处理这两种具体类型的版本，这种做法叫**单态化**。`'a: 'b` 要求前者有效期覆盖后者；`const` `N` 让数组长度成为编译期参数。这些约束也可以放进 `where` 子句。

当前记录生命周期参数名与 `Box`、`Vec` 类型实参，尚不代表用户泛型展开、完整约束检查和 `trait` 求解都已具备。

```rust
// 完整 Rust 的动态分派例子
trait Read { fn read(&self) -> i32; }
fn show(x: &dyn Read) -> i32 { x.read() }
```

`show` 通过共同接口调用具体对象的方法，可以共用这一段代码。类型擦除也会隐藏部分具体类型信息，但各语言采用的规则不同，不能把它们都当成同一做法。

按具体类型展开更有机会内联，也可能增加代码体积和编译时间；共用代码可能需要间接调用或表示转换。类型检查可以先保留参数与约束，到后面的阶段再决定具体生成方式。

扩展类型和表达式时，也要重新检查“基本组成”这个说法。文法中的 `Primary` 能包住更复杂的内容，未必已经走到树的底部。

```rust
(a + b) * c
[1, 2]
{ let x = 1; x }
```

第一行把括号加法作为乘法左侧起点，进入括号后仍能看到 `a` 和 `b` 两个更深的基本节点。单独的加号只是操作符，需要与操作数组合才形成表达式。数组与块也可能处在类似起点位置，却显然有内部内容。类型自身还有独立的递归结构，比如 `&[i32; 3]`。因此用 `Primary` 帮助读文法时，不要把所有 `Primary` 都压成最终叶子；要继续查看内部结构。

## 引用与存储

在名字表里能找到一个引用，只能说明这个名字当前可见。它指向的值是否还存在，还需要把创建、有效期和**后续使用联系起来**。

```rust
// 完整 Rust 中会被拒绝的例子
let r;
{
    let x = 1;
    r = &x;
}
println!("{}", r);
```

`r` 在外层可以被找到，但它指向内层 `x`。离开内层以后，`x` 的存储已经结束使用，外面再经 `r` 访问就有悬垂问题。生命周期检查需要把创建引用、目标有效期与后续使用联系起来。仅在局部表中记录 `r` 的类型无法完成这个判断。当前未初始化 `let`、宏与完整生命周期分析都不属于这里的已支持范围；这个例子只说明额外检查的目的。

可写性同样只回答了一部分问题。即使每次借用单独看都指向可写对象，多次借用之间也可能发生冲突。

```rust
// 完整 Rust 中的借用冲突
let mut x = 1;
let r1 = &mut x;
let r2 = &mut x;
use_both(r1, r2);
// 移动之后再使用也需要检查：
let a = Box::new(1);
let b = a;
use_box(a);
```

`r1` 与 `r2` 指向同一对象，并在后面同时使用。只检查两次 `&mut x` 时 `x` 是否可写，无法发现完整冲突。`Box` 的移动把持有资源的责任交给 `b`，随后再次使用 `a` 也需要单独检查。当前尚未完整追踪这类移动后使用。

完整 `Rust` 的 `Cell`、`RefCell` 等类型还允许按专门规则在共享访问下修改内部内容。内部可变性有自身条件，不能由普通共享引用规则随意推出。

讨论这些关系时，还经常会提到栈和堆。它们帮助说明运行时存放方式，但不要与编译器保存 AST 的那组对象混在一起。

```rust
let a = [1, 2, 3];
let b = Box::<[i32; 3]>::new([1, 2, 3]);
```

`a` 的数组直接包含三个元素，可能作为局部数据放进一次函数调用的栈帧。`b` 通过 `Box` 指向另一处数据，绑定本身保存访问它所需的信息。实际存放位置还可能受优化影响。追踪对象是否会在创建它的局部范围之外继续使用，叫逃逸分析，它可以帮助安排存储。编译器为 AST 申请的对象属于编译器自身。程序运行时的 `a`、`b` 属于另一组对象，不能把两种堆混作同一层来解释。
