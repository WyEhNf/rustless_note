## 主干与孩子

可以先按“根 → 声明 → 块中的语句 → 表达式”来理解 AST。这只是抓主干的读法；`Type` 会出现在多处，表达式里也能继续包含块。

```rust
fn add(x: i32) -> i32 {
    let y: i32 = x + 1;
    y
}
```

根下面有 `add` 这个函数声明。函数连接参数、结果类型和块；块按顺序保存 `let` 与尾表达式；`let` 的初值继续连到加法。加法最底下是名字 `x` 和整数 1。这里名字的使用叫路径，直接写出的值叫字面量。参数的 `i32`、返回的 `i32`、局部标注的 `i32`，都属于类型子树。`Type` 会出现在不同层，不能把它固定理解成只在最底层出现。

沿着主干往下走，还需要看清每个孩子在父节点里做什么。两个节点相连，并没有把这些角色差别都说完。

```rust
fn f() {
    let p = Point { x: 1, y: 2 };
    let z = p.x + p.y;
}
```

函数连到一个块，块顺序包含两条 `let`。结构体初值分别连接字段 `x` 的值与字段 `y` 的值；加法分别连接左边和右边。这些连接都形成树，却有不同含义。若把字段名丢掉，只剩 1 和 2，就无法检查是否写错字段；若交换减法的左右孩子，也会改变结果。因此读树时需要同时问：这个孩子是什么，它在父节点里担当什么角色。

**四层结构帮助我们抓主干；真正读树时，还要看每个孩子的角色。**

角色不同，孩子的数量和保存方式也会不同。调用、加法和整数放在一起，就能看到这种差别。

```rust
f(a, b)
a + b
42
```

调用包含被调用者 `f` 和两个实参；加法有左右两个操作数；整数 42 没有更深的表达式孩子。列表适合保存实参这样的多个内容。变体或类别标记帮助区分“调用”“加法”“整数”。指针只负责找到对象，名字是否指向某条声明，仍由名字查找确定。智能指针还会管理对象何时释放。转移一个指针的持有方式，可以减少复制；这件事本身不会改变树所表示的计算。

## 节点的形式

表达式统一称为 `Expr`，可以共享编号、位置和类别这些信息。真正解释它时，还要把**操作符和孩子一起看**，否则两个外形很接近的节点也可能被混淆。

```rust
a + 1
a - 1
```

两个表达式都属于二元运算，左边都用名字 `a`，右边都是整数 1。但操作符不同，所以含义不同。类别说明按二元运算处理，直接内容说明是加号还是减号，孩子说明两边参与计算的内容，编号和位置说明这是源码中的哪一次出现。把这些信息分开看，就不会把节点类别、操作符文本和操作数混成同一件事。

再把范围放大，表达式之间连外形都可能差很多。它们能够继续组合成更大的表达式，所以放在同一类概念下讨论。

```rust
1
x + 1
f(x)
{ let y = 1; y }
```

整数直接带一个值；加法带两个孩子；调用带被调用者和实参；块包含按顺序出现的语句。把它们都叫表达式，方便它们继续参与更大的表达式。文法中的 `Primary` 表示可以作为进一步运算起点的写法，例如字面量、路径与括号。它可以把复杂表达式包进去。因此“文法里有一个名字”和“AST 中必须另建一类节点”并不必然对应。树可以用类别标记或几种变体表达这些差异。
