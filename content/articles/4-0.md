## 块与语句

前面已经看过整棵树的主干，这一章继续进入函数体。主要讨论块、语句和表达式怎样相互包含，以及源码中的顺序、分号和操作符怎样体现在树里。

块本身是一种表达式，里面按顺序保存语句。`let` 语句引入绑定，需要留下名字、可变性、可选类型和初值。普通表达式语句安排一次求值；块末尾没有分号的表达式，则可以提供整个块的结果。

```rust
fn choose(flag: bool) -> i32 {
    let values = [1, 2 + 3];
    if flag { values[0] } else { values[1] }
}
```

函数体先有一条 `let`，再有一个作为尾值的 `if`。`let` 的初值是数组，数组第二个元素又是加法。`if` 有条件和两个分支块，两个块的尾部又分别是下标表达式。从块走到语句，再走到表达式，里面又能遇到块，这就是递归嵌套。

## 表达式的形式

表达式可以按几类理解。字面量和路径提供基础内容，数组与结构体把多个值组合起来。`if`、`loop`、`while` 组织分支与循环。一元、二元运算和赋值连接操作数，转换还要保存目标类型。调用、字段和下标则继续接在已有表达式后面。

例如 `make()[i].read()`，先有调用 `make`，再把它的结果作为下标的容器，最后把取出的元素作为 `read` 的接收者。每接上一段，就在前面结果外继续形成一层。

`break`、`continue`、`return` 也会出现在表达式结构里。建树时先留下跳转种类和携带的值，当前能否这样跳、返回值类型是否正确，要等语义分析结合循环和函数上下文判断。

## 分组与父子关系

```rust
1 + 2 * 3
(1 + 2) * 3
```

第一行把乘法放在加法右侧，第二行把加法放在乘法左侧。括号的作用已经进入父子关系，整理 AST 时可以省掉只负责包装的层次；真正发生的运算仍然要保留。连续转换也一样，内层转换的结果继续交给外层。

文法中的 `Primary` 表示可以继续参与运算的起点。字面量可以是起点，括号中的整个加法也可以是起点，因此 `Primary` 内部仍然可能有孩子。最终叶子与文法中的起点需要分别理解。

## 完整函数的结构

本章先把块、语句与起点写法放在一起，再讨论表达式组合、优先级和孩子的角色，最后回到完整函数沿树走一遍。条件后面的大括号属于哪里、分号是否丢弃结果、两个孩子谁在左谁在右，都在这个过程中逐项确定。

**建树先保留每个部分怎样组成整体，语义分析再沿着这些关系检查它能否成立。**

所以下一章开始讨论语义分析时，不需要重新猜源码的分组，可以直接使用这里已经得到的结构。
