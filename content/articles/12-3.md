## while 的规则

`while` 可能一次也不执行，因此这里把整个 `while` 的结果**固定为 `Unit`**。需要保留计算结果时，可以通过外部变量表达出来。

```rust
let condition = true;
let mut result = 0;
while condition {
    result = 7;
    break;
}
```

`condition` 第一次为 `false` 时，`result` 仍是 0。进入循环并赋值后，它才变成 7。`while` 条件要求 `bool`，体要求 `Unit` 或 `Never`，整个 `while` 得到 `Unit`。

这个结果保存在外部变量中，`while` 自身的类型仍为 `Unit`。若要直接由循环产生整数，可以使用[带值退出的 loop](/posts/12.2)。

这也限制了 `while` 里的 `break` 可以携带什么。常见的空 `break` 没问题，带值写法则要继续检查。

```rust
// 三行分别检查，flag 是函数体中可见的 bool。
while flag { break; }
while flag { break (); }
while flag { break 7; } // 错误
```

前两个写法都带出 `Unit`。第三个携带 `i32`，与 `while` 的固定结果不符。当前检查还会严格确认携带类型就是 `Unit`。若写 `break { return 0; };`，携带表达式成为 `Never`，也可能在这个严格判断处被拒绝。因此这里不能直接套用“`Never` 在任何地方都无条件放行”的说法，还需要看具体使用点的要求。

还有一个容易忽略的位置：`while` 的条件本身也是表达式，里面也可能出现块和循环。当前规则会单独处理这段条件的循环上下文。

```rust
loop {
    while { break; true } {} // 当前规则下没有可见跳转目标
}
while (loop { break false; }) {}
```

第一种写法在检查 `while` 条件时，看不到外层 `loop`，因此 `break` 被拒绝。第二种写法在条件内部自己建立 `loop`，`break false` 找到这个内层循环，整个 `loop` 得到 `bool`，可作为条件。条件检查结束后，再恢复外层循环上下文。这个处理属于当前讨论的具体规则，阅读嵌套跳转时要保留它。

## 跳转目标

`break` 和 `continue` 都会改变接下来的执行位置。检查它们时，要先找到当前可用的循环，再区分是否需要登记带出的值。

```rust
loop {
    loop { break; }
    continue;
}
// 在普通函数体内单独写 break;，没有循环目标。
```

内层 `break` 结束内层 `loop`，之后 `continue` 针对外层 `loop`，进入外层下一轮。`break` 还需要检查携带值，并记到对应循环中；`continue` 无需加入结果列表。两者自身都表现为 `Never`。完整 Rust 的带标签跳转可以指定更外层目标。当前没有保存标签的结构，因此这些例子只讨论最近循环。

`return` 的目标则由当前函数确定。即使没有显式携带值，也需要检查实际提供的 `Unit` 能否符合函数要求。

```rust
fn a() { return; }
fn b() -> i32 { return 1; }
fn c() -> i32 { return; } // Unit 与 i32 不匹配
```

`a` 要求 `Unit`，所以空 `return` 合适。`b` 把 `i32` 要求传给 1，携带值符合签名。`c` 没有携带值，并不能因为函数写了 `i32` 就自动补上整数。它实际提供 `Unit`，因此出错。`return` 自身在当前表达式位置是 `Never`。这个性质说明控制流，不替代对携带值的检查。
