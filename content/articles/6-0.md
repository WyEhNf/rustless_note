## 全局名字登记

这一章展开 `Pass1` 的前半部分：收集名字、确定所属关系，再解析声明中的类型。核心问题是，后面检查一个表达式时，怎样知道它找到的是哪条声明，以及这条声明提出什么要求。

名字需要按用途分类。类型命名空间和值命名空间可以理解成两套分别查找、分别检查重复的名字集合。结构体名字主要用于找类型，函数和常量主要用于找值或调用目标。同一类中重复的全局定义要报告，局部 `let` 的遮蔽则留到函数体中处理。

```rust
struct Buffer { data: [i32; Buffer::N] }
impl Buffer {
    const N: usize = 3;
    fn size(&self) -> usize { Self::N }
}
fn main() {}
```

`Buffer` 的字段使用了写在后面的关联常量。要解释这个类型，先得让 `Buffer` 和 `Buffer::N` 都可以被查到。于是名字的登记与声明内容的继续检查需要分开安排，不能读到第一条声明就要求所有依赖都已经彻底结束。

## impl 与所属类型

`impl` 本身没有一个供调用的名字，它先说明这组成员属于哪个类型。这里目标是 `Buffer`，`N` 和 `size` 就归到 `Buffer` 下面。之后 `Self::N` 可以根据所属类型解释成 `Buffer::N`。

同一个类型可能有多个 `impl`，但成员的所属类型仍然相同，因此成员查重也要跨这些 `impl` 进行。找不到目标结构体，就无法继续建立相应关系；当前允许的用户 `impl` 目标也有范围限制。

关联查找只需要登记实际出现的成员。使用处写 `Buffer::missing`，再去表中查询是否存在即可。任意模块路径、导入和可见性需要更完整的规则，本章先讨论结构体关联项。

## 类型与签名

名字准备好后，声明中的 `Type` 开始得到确定含义。引用继续解析所指类型，数组继续解析元素与长度，`Self` 结合 `owner` 解释，`Box` 和 `Vec` 检查元素类型实参。例子中的数组最终还需要求出 `N` 的值，才能得到 `[i32; 3]`。

函数签名记录参数和返回类型，方法还带着 `self` 的要求。声明阶段先确定这些类型并检查参数名字是否重复；进入函数体时，才把参数名与类型组成局部绑定。结构体字段也留下类型和声明身份，供后面构造值或访问字段时使用。

## 声明的使用限制

```rust
fn add(x: i32, y: i32) -> i32 { x + y }
add(1, 2);
add(true, 2); // 参数类型不符合
add(1);       // 参数数量不足
```

三个调用都能找到 `add`，但只有第一个同时满足签名要求。**找到声明以后，还要根据它的要求检查使用方式。**

本章会把名字分类、内建名字保护与 `impl` 登记放在一起，再讨论类型解析、函数签名及查找后的检查。完成这些准备以后，常量依赖、有限大小和 `derive` 仍需继续确认，接下来的两章就处理这些问题。
