## 共享表示、复用与查找

一份程序可能反复出现相同的名字或类型写法。共用它们的文本或规范表示，可以减少重复保存；每条声明自己的身份仍然要保留。

```rust
let x = 1;
{
    let x = true;
    let y = x;
}
```

两个声明都用文字 `x`，可以共用一份文本或文本编号。这种集中保存名字的做法叫字符串驻留。它们的**声明身份仍然不同**，内层 `y` 必须找到 `bool` 绑定。把文本编号当成唯一声明身份，会破坏遮蔽规则。同样，重复出现的 `&[i32; 3]` 可以共享规范类型表示，以减少分配与比较。当前的声明编号、字符串查找和类型对象仍各有自己的用途。

例如许多地方都写 `Box<Vec<i32>>`，规范化后可以共享同一类型表示，比较时直接比较编号。紧凑保存查找记录也可能减少分散访问，但速度改善需要测量；未使用类型的部分信息还可以等真正需要时再展开。

检查结果也可以考虑重复使用。不过源码变化以后，要知道哪些结果仍然适用，就需要继续记录它们依赖了什么。

```rust
fn inc(x: i32) -> i32 { x + 1 }
fn main() { let y = inc(3); }
// 修改：把 inc 的函数体换成 x + 2。
```

签名没有变化时，调用者的参数要求可能继续有效，但 `inc` 的执行内容已经改变，需要重新处理相关部分。如果把返回类型也改了，依赖这个结果的调用就可能需要重新检查。保存结果叫缓存，按变化范围重算叫增量处理。互不依赖的部分还可能并行分析，前提是共享信息与完成顺序安排正确。当前按一次完整输入重新建立记录，已有类型结果不等于通用增量缓存。

```rust
const A: usize = C;
const B: usize = C;
const C: usize = 3;
```

`C` 求完后，`A` 与 `B` 可以复用它。更大的依赖图还可按依赖顺序处理，或找出相互可达的一组节点，这叫强连通分量。Tarjan 是寻找这类分组的一种算法；算法是否递归、怎样控制调用深度，仍取决于具体写法。

更完整的名字与方法查找也会引入新依赖：模块、导入别名、可见性和泛型约束都可能参与决定最终目标。

```rust
// 完整 Rust 的例子
mod shapes { pub struct Point { pub x: i32 } }
use shapes::Point as P;
let p = P { x: 1 };
fn duplicate<T: Clone>(x: T) -> T { x.clone() }
```

`P` 先经导入别名找到 `shapes` 中的公开 `Point`；字段 `x` 也需要允许外部访问。泛型 `x` 的 `clone` 则依赖 `T`: `Clone`，不能只按固定结构体名查找。方法决议就是根据这些依据选择具体方法。不同库还需要避免相互冲突的实现；孤儿规则会限制为外部类型实现外部 `trait`，具体允许形式还有更细规定。当前关联表主要处理实际出现的结构体成员，通用模块和约束求解仍需扩展。
