## 错误恢复与后续检查

一处出错后，后面可能还有互不依赖的问题。适当地保留临时结果并继续检查，可以一次给出更完整的错误信息。

```rust
fn f(x: i32) {}
fn main() {
    f(true, missing);
    let y = another_missing;
}
```

第一处调用有参数数量错误、`bool` 与 `i32` 不匹配，以及 `missing` 未定义。继续到下一行还能发现 `another_missing`。`Error` 类型可以暂时作为占位，减少由同一处失败反复引出的消息。

结构体未知字段的值也能继续检查。比如已声明 `Point { x: i32 }` 时，下面一行同时有字段与名字错误：

```rust
let p = Point { x: 1, extra: missing };
```

`x` 已经提供，`extra` 是额外的未知字段；继续读它的初值，还能找到未声明的 `missing`。这里同时保留两个错误，用来说明字段名失败后，初值仍有能够独立检查的内容。

继续检查和继续生成正常程序需要分开判断。记录表里已经有一些结果，也可能仍然存在足以阻止程序通过的错误。

```rust
fn main() {
    let a = 1;
    let b: bool = 2; // 错误
}
```

`a` 可以得到完整类型结论，`b` 也可能留下临时记录，但 `bool` 初值错误仍然存在。检查结束后需要**统一查看错误状态**，有错误就停止正常代码生成。某个常量被标为已处理、某个函数返回了对象，都不能替代整份程序的判断。这样既允许一次报告多个问题，也避免把用于继续分析的临时内容误当成最终合法程序。

这些错误还需要回到源码中的准确位置。建树时留下的范围，在这里就能帮助读者找到要修改的内容。

```rust
let a = 1 + true;
let b = missing;
let p = Point { x: 1, wrong: 1 }; // 假定 Point 只有字段 x
```

第一行需要指出加法中不合适的操作数，第二行指出未知名字，第三行指出未知字段 `wrong`。节点或字段初值保存的范围让这些消息能回到正确行列。把第一行移到文件后面，错误原因不变，位置应跟着改变。完整工具还可以用位置支持编辑器跳转和调试显示。这里首先关注读者能准确找到要修改的源码。
