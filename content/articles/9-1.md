## 函数的检查上下文

进入一个函数时，全局声明已经准备好。接下来要记住**当前函数要求什么结果**，把参数放进局部作用域，并为块和循环分别维护上下文。

```rust
fn a(x: i32) -> i32 { x }
fn b() -> i32 { x } // 错误：看不到 a 的参数
```

检查 `a` 时，把参数 `x` 放进它自己的作用域，并记住当前结果要求是 `i32`。退出后，`b` 不能继承这层参数表。函数体中的块继续增加局部层次。循环上下文则在进入与退出循环时成对维护，不能让一个函数里的循环成为另一个函数的跳转目标。已经完成的声明表可以共用，当前函数、参数与块作用域则需要分别处理。

参数类型来自前面确定的签名。现在要把这个类型和参数名字、可变性、声明身份连起来，供函数体使用。

```rust
fn inc(mut x: i32) -> i32 {
    x += 1;
    x
}
```

签名已经说明参数是 `i32`。进入 `inc` 后，把 `x` 记成一个可变的 `i32` 绑定，并保留参数声明的身份。函数体本身再形成一层块作用域。查 `x` 时从块内向外，最终找到参数层。删掉参数前的 `mut` 后，读取 `x` 仍然成立，但 `x += 1` 无法通过写权限检查。参数类型相同，也可以有不同的绑定权限。

## self 与 Self

方法多了一个接收者。可以把 `&self` 理解成“名字为 `self`、类型为当前结构体的共享引用”的参数，这样它就能像其他局部名字一样被查到。

```rust
struct Counter { value: i32 }
impl Counter {
    fn read(&self) -> i32 { self.value }
    fn add(&mut self, n: i32) { self.value += n; }
}
```

`read` 属于 `Counter`，因此 `self` 的类型是 `&Counter`；`add` 中则是 `&mut Counter`。方法体都可以通过局部名字 `self` 查到接收者。这种展开帮助理解点号调用为什么要提供一个对象。接收者也参与类型和权限检查。不必真的往原语法树中塞入一个新参数节点，检查时直接建立相应绑定，同样可以供方法体查找。

写方法时还会遇到**大写 `Self`**。它与小写 `self` 的用途不同，放在同一个方法里看会更清楚。

```rust
struct Counter { value: i32 }
impl Counter {
    const LIMIT: i32 = 10;
    fn room(&self) -> i32 { Self::LIMIT - self.value }
}
```

`Self::LIMIT` 根据所属类型展开为 `Counter::LIMIT`，找到关联常量。`self.value` 则先找到局部接收者，再访问它的 `value` 字段。`Self` 需要类型所属关系，`self` 需要当前方法的局部绑定。普通顶层函数没有所属结构体，不能凭空使用方法式接收者。把二者分开，就能同时看清“到哪个类型下面找成员”和“对哪个具体值做操作”。

## 尾值与返回

函数声明已经给出返回类型。函数体可以通过尾表达式提供这个类型的值，也可以用 `return` 提前返回；这两条路径需要分别理解。

```rust
fn a() -> i32 { 1 }
fn b() -> i32 { return 1; }
fn c() -> i32 { return true; } // 错误
```

`a` 的块把 `i32` 期望交给尾部整数。`b` 的 `return` 按当前函数结果检查 1，然后自身得到 `Never`。这个类型表示表达式没有正常继续的结果；它已经把执行带到了函数之外。`c` 虽然同样跳走，携带值 `true` 仍是 `bool`，无法作为 `i32` 返回。持续发散的函数体可以满足结果要求，因为它没有正常返回的路径。这个规则不会免除 `return` **携带值的检查**。
