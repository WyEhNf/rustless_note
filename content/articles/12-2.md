## break 与结果

`loop` 可以通过 `break` 带出一个值。检查时为当前循环单独收集这些值，再结合外层 `expected` 决定整个 `loop` 的结果类型。

```rust
let x: i32 = loop {
    if flag { break 1; }
    break 2;
};
```

两个 `break` 都属于同一个 `loop`，携带值都按外层 `i32` 期望检查，因此 `loop` 可以产生 `i32`。循环体本身要求 `Unit` 或 `Never`；`break` 自身跳走，符合这个要求。检查结束后取出当前循环记录，再恢复外层循环。若内部又有一个 `loop`，它的 `break` 先归到内层，不能直接混进外层的结果列表。

这里要区分 `break` 自身的类型和它携带的类型。一个说明当前执行会跳走，另一个说明 `loop` 退出后给外面什么值。

```rust
let x = loop { break 1; };
let y = loop { break; };
loop { continue; }
```

第一行带出整数，`loop` 得到 `i32`；第二行没有显式值，带出 `Unit`。两次 `break` 在体内都不会正常继续到下一步。`continue` 只转到下一轮，不为循环登记退出结果。没有收集到 `break` 的 `loop` 可以按 `Never` 理解。把 `break` 自身类型与它携带的类型混在一起，会让循环体要求和循环整体结果看起来互相矛盾。

**`break` 自身跳走，携带的值则用来决定 `loop` 的结果。**

当多个 `break` 的携带类型不同，选择共同结果的顺序也可能影响当前检查。下面这个例子保留了对话中特别讨论的边界。

```rust
fn f(flag: bool) -> i32 {
    let x = loop {
        if flag { break { return 0; }; }
        break 1;
    };
    x
}
```

第一个 `break` 的携带块先 `return`，因此携带类型是 `Never`；第二个携带 `i32`。没有给 `x` 标注时，当前规则可能先选 `Never`，再发现 `i32` 无法适配它。若先选到 `i32`，后来的 `Never` 则可以适配。对话中提出过先跳过 `Never`、再选正常结果的改进，但当前规则尚未采用。

给 `x` 明确 `i32` 期望可以说明目标要求。这一例子用受支持的 `return` 块表达发散，无需引入 panic 宏。
