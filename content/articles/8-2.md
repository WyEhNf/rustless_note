## 字段能力

`derive` 表示希望根据字段，为结构体提供某种能力。这里讨论 `Copy`、`Clone`、`PartialEq` 和 `Eq`；列出这些名字之后，还需要检查它们之间的要求以及**字段本身**。

```rust
#[derive(Copy, Clone, PartialEq, Eq)]
struct Point { x: i32, y: i32 }
```

`Copy` 允许复制后继续使用原值，`Clone` 提供显式 `clone`。`PartialEq` 支持相等比较，`Eq` 进一步要求相等关系具有自反性，即值应当等于自身。这里请求 `Copy` 时要同时写 `Clone`，请求 `Eq` 时要同时写 `PartialEq`。重复写同一种 `derive` 也需要报告。

`Point` 的字段都是 `i32`，随后再按字段规则确认这四种能力。仅把名字列在 `derive` 中，还没有完成检查。

声明形式符合要求后，继续走到字段类型。基础类型、引用、数组和容器各自有相应规则。

```rust
#[derive(Clone)]
struct Bag { values: Vec<i32> }
#[derive(Copy, Clone)]
struct Pair { x: i32, y: bool }
```

整数、`bool` 和 `Unit` 支持这里的基础能力。数组继续检查元素；用户结构体需要相应 `derive`，也需要字段通过检查。共享引用支持 `Copy` 与 `Clone`，可变引用在这里两者都不支持。引用的相等能力则继续看所指类型。

`Box`、`Vec` 不支持 `Copy`，`Clone` 与相等能力继续看元素。于是 `Bag` 可以检查 `Clone`，`Pair` 的两个字段可以支持 `Copy` 与 `Clone`。

上面的 `Bag` 如果再请求 `Copy`，就会被 `Vec` 字段阻止。`Clone` 与 `Copy` 虽然都涉及复制，却有不同的类型要求。

`Vec` 持有一组元素，`Clone` 需要按元素能力处理内容。给 `Bag` 加上 `Copy`，不能绕开 `Vec` 本身不支持 `Copy` 的规则。共享引用的 `clone` 则复制引用，仍指向原来的目标。

因而“`Clone` 一定把整份目标数据复制一遍”也过于笼统。当前类型能力检查与实际提供哪些用户可调用的 `clone` 接口还要分开；具体调用范围在后面的调用文章中讨论。

## 递归字段

有些结构会再次指向同一种类型，却仍然具有有限大小。接下来能否支持 `Copy` 或 `Clone`，需要再看它是怎样引用内部内容的。

```rust
// 引用关系示意；这里只分析大小与能力，生命周期检查不在当前范围内。
#[derive(Copy, Clone)]
struct Link<'a> { next: &'a Link<'a> }
```

计算 `Link` 的形状时，到了引用这一层就能停止内联展开。检查 `Copy` 时，共享引用自身支持复制，也不再递归复制整个 `Link`。因此这里有指向同类型的关系，同时可以通过这项能力检查。这只说明类型层面的规则。怎样得到一个有效的引用、它能保持多久，还属于生命周期与值构造的问题。

把共享引用换成 `Vec` 后，大小仍然可以有限，能力检查却要继续考虑元素。

```rust
#[derive(Clone)]
struct Tree { children: Vec<Tree> }
```

`Vec` 让 `Tree` 的对象形状有限。检查 `Clone` 时，继续要求元素 `Tree` 具有 `Clone`，并处理这种递归出现。空 `children` 可以构成叶子，所以具体树可以是有限的。实际 `clone` 会沿具体元素继续处理。若改为请求 `Copy`，`Vec` 这一层就会拒绝。不能因为它隔开了内联关系，就认为它支持任意复制能力。

元素类型又回到当前结构体时，检查需要避免一直重复同一条路径，同时继续检查其他字段。

```rust
#[derive(Clone)]
struct Tree {
    children: Vec<Tree>,
    value: i32,
}
```

从 `Tree` 进入 `Vec`，再回到 `Tree` 时，当前规则对非 `Copy` 能力允许停止这条重复路径；`value` 等其他字段还要照常检查。每个字段应使用自己的访问路径。否则前一个字段留下的标记可能让后一个字段被错误地当作已经完成。这种处理让类型检查能够结束。具体值上的 `clone` 或比较是否终止，仍要看运行时的数据关系。
