## 字面量

表达式递归到底部时，经常会遇到整数、布尔值和 `Unit`。它们的写法很简单，但类型如何确定、结论存到哪里，仍然需要说明。

```rust
let n: usize = 3;
let flag = true;
let empty = ();
```

3 在 `usize` 期望下取 `usize`；`true` 固定为 `bool`；`()` 固定为 `Unit`。三者各有语法节点，但通常没有需要关联的声明。整数取型沿用[后缀与期望的规则](/posts/10.1)。确定后，通用的表达式检查过程把结论记下来。因此记录结果的表必须**按节点工作**。仅用名字作键，会漏掉这些没有名字的基本表达式。

尤其是无后缀整数，在不同位置可能获得不同的 `expected`。把调用和下标放在一起，就能看清要求来自哪里。

```rust
fn take(x: u32) {}
let a = [10, 20];
take(3);
let x = a[1];
printlnInt(3);
```

`take` 的参数要求 `u32`，所以 3 可以取 `u32`。数组下标要求 `usize`，因此无后缀的 1 取 `usize`。`printlnInt` 的实参则要求 `i32`。这些位置的差别在于要求的来源。把下标改成 `a[1i32]`，显式后缀保留 `i32`，索引位置便发现不匹配；函数签名与下标规则各自决定怎样使用字面量结果。

## 名字查找

检查路径时，需要先把依赖当前位置的写法解释清楚。例如 `Self` 要结合当前所属类型，才能形成可查的关联名。

```rust
struct Point { x: i32 }
impl Point {
    const N: i32 = 3;
    fn n() -> i32 { Self::N }
}
```

方法 `n` 属于 `Point`，因此 `Self::N` 可以整理为 `Point::N`。把路径段用双冒号连接以后，就能查相应关联常量。如果没有当前所属类型，就无法随意解释 `Self`。找到常量以后，还要取得它的声明类型和值。这里的展开只是让同一种含义有一致的查找写法，不会把常量引用变成一次运行时字段访问。

单段名字按照[作用域规则](/posts/9.2)先查局部绑定。这里继续看局部查找与全局声明怎样衔接。

```rust
const X: i32 = 1;
fn main() {
    let X = true;
    let y = X;
}
```

`y` 的初值首先找到局部 `X`，因此是 `bool`。全局常量 `X` 仍然存在，只是这次使用被局部绑定遮住。当前查找顺序继续包括全局常量、全局函数、内建函数和结构体候选。局部变量带有位置与绑定权限，常量通常作为值，函数则提供调用目标。同一个拼写可能来自不同范围，所以不能只凭文本把所有 `X` 记成同一个声明。

多段关联名继续到相应的关联表查找。内建容器路径还可能带类型实参，找到候选后也要继续检查这些要求。

```rust
struct A {}
impl A { fn b() {} }
fn main() {
    A::b();
    A::c(); // 错误：没有 c
}
```

关联表中登记了 `A::b`，所以第一处可以继续检查签名。`A::c` 没有声明，也不属于受支持的内建候选，因此找不到目标。`Vec::<i32>::new` 则还要确认类型实参数量，以及 `new` 是否接受当前值实参。即使目标出错，实参中独立存在的问题仍然可以继续检查，避免一次只发现最外层错误。

路径分成多段，与表达式层层嵌套是两回事。把关联调用与连续后缀放在一起，可以看清它们各自如何展开。

```rust
Point::get(&p)
make()[i].get()
```

第一行的 `Point::get` 可以作为一个多段路径，查到关联函数后再检查实参。第二行则依次有调用、下标、方法调用，多层表达式相互包含。当前关联值路径按完整名字查表，拼接与哈希需要处理路径文字。它不等于逐层实现了所有模块功能。通用模块、导入别名和可见性还需要专门规则。保存了任意长路径的写法，不能自动保证每种路径都能找到声明。
