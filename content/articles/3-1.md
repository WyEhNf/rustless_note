## Type：类型子树

类型写法本身也可以形成一棵树。读 `&mut Vec<[i32; 3]>` 时，从最外层开始，一层层说明它里面装着什么，比只盯着 `i32` 更清楚。

```rust
fn use_values(values: &mut Vec<[i32; 3]>) {}
```

最外层 `&mut` 表示可变引用；它指向 `Vec`；`Vec` 的元素是长度为 3 的数组；数组元素才是 `i32`。`&T` 提供共享访问，`&mut T` 允许经引用修改目标。创建引用叫借用，沿引用访问目标叫解引用。`Vec` 保存可变数量的元素，`Box` 持有一个经指针访问的值。

这里讨论的类型写法主要有 `Unit` `()`、路径、引用和固定长度数组。`i32`、用户结构体、`Box` 与 `Vec` 都可以通过路径写出。后面用 `u32` 表示 32 位无符号整数，`isize` 表示随目标大小确定的有符号整数，`bool` 表示真假值。数字后写 `3usize` 这样的后缀，就是直接指定它的类型。

如果数组长度写成一个名字，这一层还会连到编译期求值。建树时先保留写法，等有足够信息后再确定长度。

```rust
const N: usize = 3;
fn use_row(row: &[i32; (N)]) {}
```

`row` 是共享引用，引用目标是数组，数组元素是 `i32`。长度位置保存了 `(N)` 这个写法。建树时可以先保存括号里的名字和长度文本，等名字查找与常量求值完成，再确定长度是 3。此时不能仅凭字母 `N` 猜出数组有多大。`()` 单独表示 `Unit`；包住其他类型的括号则可以继续进入内部。路径上出现的类型实参，也要按同样方式继续读取。

引用也可以再包一层引用。此时每层是否可变都各有含义，不能只看最里面的类型。

```rust
let mut n = 1;
let r = &mut n;
let rr = &r; // 类型形状为 &&mut i32
```

`rr` 先通过共享引用找到 `r`，再由 `r` 指向整数。最外层共享，内层可变，这两个信息都要保留。类型转换也可以接上类型子树，例如 `n as u32` 的目标是 `u32`。

连续转换会形成表达式嵌套，每个目标位置分别连接自己的类型子树。[转换与表达式组合](/posts/4.2)会沿这条链继续分析。

**类型的每一层都要保留：外面的访问方式和里面的元素类型共同决定含义。**

## 语义类型

看到一种类型的外形，只能知道接下来该怎样处理。里面的名字指谁、数组究竟多长，还需要继续查清楚。

```rust
let a: [i32; 3];
let b: [bool; 3];
let c: [i32; 8];
```

三者都是数组，但 `a` 与 `b` 的元素类型不同，`a` 与 `c` 的长度不同。只比较“数组”这个类别，会把不同要求混在一起。引用还要比较所指类型和 `mut`；结构体要知道具体是哪一个声明。类型对象正是把这些信息放在一起。源码中的类型树保存写法，解析后的语义类型保存确定含义。文中用 `Type` 指源码类型写法，用 `Ty` 简称解析后的语义类型。

这些信息确定后，同一种语义类型可能来自不同的源码写法。后续比较应当使用**已经解析出的结果**。

```rust
struct Point { x: i32 }
impl Point {
    const N: usize = 3;
    fn f() { let a: [i32; Self::N]; }
}
```

`Self` 表示当前 `impl` 所属的 `Point`。因此 `Self::N` 指向 `Point::N`，求值后长度是 3，`a` 的类型就确定为 `[i32; 3]`。不同位置重复写这个类型，会形成不同的语法节点；比较类型时，仍可以确认它们有相同的元素与长度。这种相等来自内容比较。两个类型对象是否恰好放在同一个地址，是另一回事。
