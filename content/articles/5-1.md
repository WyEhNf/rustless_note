## 声明顺序与调用

源码中的声明顺序，可以和函数运行时的调用顺序不同。语义分析先收集整份程序中的声明，调用处就能够使用写在后面的函数签名。

```rust
fn main() { let x = later(1); }
fn later(x: i32) -> i32 { x + 1 }
```

`main` 需要知道 `later` 接收什么、返回什么。Pass1 读出 `later` 的参数与返回类型均为 `i32`，把这个签名留在声明记录中。Pass2 进入 `main` 后，整数 1 可以按参数要求检查，调用整体再给 `x` 提供 `i32`。

这一步无需执行 `later`。即使 `later` 自己调用另一个函数，当前调用仍先按已有签名检查；各个函数体随后各自接受检查。声明身份与声明上的要求因此能够供多个使用处共同引用。

## 类型中的依赖

声明本身也可能用到别的声明。字段中的数组长度，就需要先取得常量值。

```rust
const N: usize = 2;
struct Row { data: [i32; N] }
fn first(row: &Row) -> i32 { row.data[0] }
```

`Row` 的字段类型需要元素类型 `i32` 和长度 `N`。登记 `N` 让这个名字有处可查，求出值 2 才能确定完整数组类型。`first` 的签名还要解析 `&Row`，函数体里的字段访问才能继续取得 `[i32; 2]`，再从下标得到 `i32`。

因此 Pass1 包括名字登记、声明类型解析和所需常量求值，也检查对象大小、派生能力与程序入口。这里的依赖，就是处理一项内容时还需要先知道的另一项信息。具体顺序随着这些需要确定，不能把所有声明都理解成读一次名字便已经完成。

## 使用处的结论

同一声明提供的要求固定下来后，不同使用处仍会有不同结果。

```rust
fn positive(x: i32) -> bool { x > 0 }
fn main() {
    let a = positive(1);
    let b = positive(true); // 实参类型不符
}
```

两处调用都找到 `positive`，得到相同签名。`a` 的实参满足 `i32`，调用结果为 `bool`；`b` 的实参是 `bool`，无法满足这个参数。错误发生在具体使用处，不能仅凭全局表里已经存在函数就放过调用。

函数体还会引入局部名字，表达式也可能通过字段、下标或引用访问一个值。类型要求、名字范围和写权限都要结合当前位置判断。它们各自的规则在 Pass2 中展开；眼下需要看清的是，声明记录提供共同依据，使用处另有自己的检查结论。

**一条声明可以被多处使用，每一次使用都要按自己的表达式结构接受检查。**
