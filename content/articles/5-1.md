## 声明与使用

AST 已经把程序的结构组织好。语义分析接着问：名字能否找到，类型能否配合，这个位置是否允许写入。这里把工作分为两遍，Pass 就表示这样一个处理阶段。

```rust
fn main() { let x = later(1); }
fn later(x: i32) -> i32 { x + 1 }
```

第一遍先知道 `later` 接收 `i32`、返回 `i32`。第二遍读到 `main` 中的调用时，就能检查实参 1。第一遍还包括解析声明类型、求常量值、检查结构能否有限存放、检查 `derive` 和 `main`。第二遍主要进入函数体，确认类型与访问权限，并记下结论。符号表示供名字查找的声明身份；依赖表示处理当前内容前还需要知道什么。分阶段的顺序由这些需要决定。

### Unit 与 Never

准备好声明后，第二遍会进入函数体。这里有一个贯穿后文的认识：块、`if` 和 `loop` 都可以作为表达式参与求值。

```rust
fn choose(flag: bool) -> i32 {
    let x = if flag { 1 } else { 2 };
    x
}
```

`if` 的两条分支都给出整数，所以整个 `if` 可以作为 `let` 的初值。函数体也是块表达式，尾部 `x` 给出 `i32`。`()` 是 `Unit` 的值，表示正常结束但没有额外数据。

`return 1` 则直接离开函数，当前表达式不会正常落到下一步，它的类型称为 `Never`。因此“很多结构都是表达式”很有帮助，但 `let` 引入绑定、`fn` 声明函数，仍有各自的结构与规则。

### 节点与声明

要把这些表达式的结论留下来，还得区分“哪一次出现”和“引用了哪条声明”。`NodeId` 与 `SymbolId` 就分别表示这两件事。

```rust
let x: i32 = 1;
let y = x + x;
```

两个 `x` 使用点有不同 `NodeId`，找到同一个 `x` 声明后，可以记录相同的 `SymbolId`，并得到 `i32`。声明节点的编号可以直接拿来当 `SymbolId`，无须再人为增加一次身份。

加法也有自己的 `NodeId`，但它通常只产生结果，没有一个直接关联的声明。`Type` 指源码中的类型写法；语义类型表示解析后的含义。后文出现 `Ty` 时，可以把它理解为语义类型的简称。

### expected：上下文的要求

声明身份确定后，函数签名便能为调用提出具体要求。把上下文希望得到的类型称为 **`expected`**，实际表达式还要在这个要求下继续检查。

```rust
fn positive(x: i32) -> bool { x > 0 }
let a = positive(1);
let b = positive(true); // 错误
```

`positive` 的签名说明它接收一个 `i32`，返回 `bool`。检查第一个实参时，1 得到 `i32` 的 `expected`，结果满足要求。第二次调用的 `true` 固定为 `bool`，无法按 `i32` 使用，因此发生类型不匹配。调用目标存在，并不能跳过这一步。出错后可以用 `Error` 作为临时占位类型，继续检查其他内容，减少同一处错误引起的重复消息。

### scope：可见名字的范围

不过，同样的名字在不同位置可能找到不同声明。这就需要作用域，也就是当前位置可以使用的名字范围。

```rust
let x = 1;
{
    let x = true;
    let a = x;
}
let b = x;
```

内层 `a` 找到 `bool` 类型的 `x`；离开大括号后，`b` 又找到外层的整数 `x`。内层绑定暂时遮住外层，这叫 `shadowing`。每个 `Binding`，也就是绑定记录，会留下类型、可变性和声明编号。

把各层表按进入顺序放成栈，就能先查最后进入的那一层。这里“名字 → 绑定”表示用名字找到记录。哈希表按键查找，有序表按键排列；选择哪一种存放方式，不会改变作用域规则。

### 隐式调整：省略的操作

查到名字、检查完类型以后，有些源码中省略的操作也需要记下来。方法调用可以说明为什么仅有一个结果类型还不够。

```rust
struct Point { x: i32 }
impl Point { fn get(&self) -> i32 { self.x } }
let p = Point { x: 1 };
let n = p.get();
```

方法要求 `&self`，调用却直接写 `p`。检查器确认可以借用 `p` 后，会记录这次自动借用，并确定调用目标是 `Point` 的 `get`。这些保留下来的结论称为表达式事实。临时检查结果可以先用于父表达式，再按节点编号存起来。隐式调整表示源码省略但需要补上的操作。多步调整要按顺序保存，否则后面无法知道先解引用还是先借用。

### place：可定位的位置

这些记录还包括访问的性质。表达式可能定位到一处存储位置，这称为 **`place`**；这个位置能不能改动，则要继续看写权限。

```rust
let mut x = 1;
let y = 2;
x = 3;
y = 3;     // 错误：绑定不可变
(x + y) = 4; // 错误：加法整体不指向存储位置
```

`x` 和 `y` 都能定位各自的存储位置，但只有 `x` 的绑定带 `mut`。加法把值拿来计算，其整体通常只产生新值。访问时还可能经过共享引用；这种路径会留下限制，后面不能遇到一个内部可变引用就恢复写权限。调用则需要记下目标，比如 `Point::get`。类型、`place`、可写性和调用目标共同说明当前表达式应当怎样使用。

**类型、声明身份与访问权限要一起看，才能说明一个表达式怎样使用。**
