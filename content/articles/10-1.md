## expected 的传递规则

`expected` 表示当前位置希望得到什么类型。检查时可以把要求往下交给孩子，再拿到孩子的实际结果，逐层形成整个表达式的结论。

```rust
fn take(x: u32) {}
fn main() { take(1); }
```

调用先找到 `take` 的签名，知道第一个参数需要 `u32`，再以这个期望检查整数 1。1 没有后缀，因此使用整数 `expected`，得到 `u32`。这个结果返回调用处，调用确认它符合签名。字段初值、带标注的 `let` 与函数尾值也能提供要求。递归最终到达字面量或路径等基本内容，再逐层向上形成整体结论。

调用、借用和名字使用都属于 `Expr`，能够继续形成表达式内部的层次。这里有两种关系需要分清：AST 的父子连接说明表达式如何组成，名字查找则把使用处连到声明。调用会同时用到这两种关系。

```rust
fn read(x: &i32) {}
let b = Box::<i32>::new(3);
read(&b);
```

调用节点的孩子包括被调用者 `read` 和实参 `&b`；借用表达式 `&b` 还包含名字 `b`。这里有连续的表达式父子关系。`read` 的函数定义是另一条顶层声明。调用中的名字通过符号查找找到它，读取签名，才知道实参最终需要 `&i32`。

`b` 自身仍是 `Box<i32>`，不能为了满足外层要求就改写它的既有类型。借用先形成 `&Box<i32>`，随后再按允许的规则调整。

`expected` 有了来源，也还要看每一种表达式怎样使用它。当前规则里，外层要求并不会原样传给所有孩子。

```rust
let a: u32 = 1;
let b: u32 = 1 + 2; // 当前二元检查规则下不匹配
let c: u32 = 1u32 + 2;
```

`a` 直接把 `u32` 交给字面量。二元运算则先独立检查左侧，`b` 的 1 先取默认 `i32`，再把 `i32` 给右侧，整体仍得到 `i32`。`c` 的左侧后缀明确了 `u32`，所以右侧也能按 `u32` 检查。数组可以传元素期望，`if` 可以传给两支，块可以传给尾值。

`cast` 先独立检查原值，再处理目标类型。不能为了让 `x as u32` 得到 `u32`，就强迫 `x` 原本也必须是 `u32`。

**`expected` 怎样往下传，要看当前表达式和孩子各自的角色。**

## 整数的类型推导

同一个数字可以出现在不同的类型要求下。这里按**后缀、整数 `expected`、默认 `i32`** 的顺序确定类型，明确写出的后缀不会被外层期望覆盖。

```rust
let a = 1u32;
let b: usize = 1;
let c = 1;
let d: i32 = 1u32; // 不匹配
let e: bool = 1;   // 不匹配
```

`a` 明确为 `u32`，`b` 使用 `usize` 期望，`c` 默认 `i32`。`d` 的期望不会覆盖显式 `u32` 后缀。`e` 的 `bool` 期望不能把数字 1 自动变成 `true`。数字仍按整数规则取型，外层再发现不匹配。布尔字面量 `true` 固定为 `bool`，`()` 固定为 `Unit`。确定字面量类型后，同样要按节点记录结果。

确定类型之外，还需要读取数字并检查范围。这一步要结合当前规则实际检查到哪里，尤其要留意负号在语法树中的位置。

```rust
let a = 4294967295u32;
let b = 4294967296u32; // 超出 32 位无符号范围
let c = -1i32;
```

`a` 达到 32 位无符号最大值，`b` 再多一就越界。这里先去后缀，读取无符号数值并检查这个上界。当前还没有在这一步完整检查 `i32`、`isize` 的有符号上下界，因此不能把一般整数规则都说成已经落实。`c` 的负号是外层操作，内部先保存字面量。处理最小负数等边界时，需要把这种结构一起考虑。
