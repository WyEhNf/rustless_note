## 值与位置

这一章把运算和写权限放在一起讨论。表达式能得到什么类型，只回答了其中一部分；借用、解引用和赋值还需要知道它能否定位到存储位置，以及沿当前路径是否允许修改。

能定位到某处存储的表达式称为 `place`。变量、字段、下标和显式解引用都可能得到这样的位置。加法通常读取操作数并产生新值，整个加法不能直接成为赋值目标。得到 `place` 以后，还要继续检查它是否可写。

```rust
let mut n = 1;
let r = &mut n;
*r = 2;
let shared = &r;
**shared = 3; // 经过外层共享访问，不能这样修改
```

`r` 的绑定没有 `mut`，但它保存可变引用，因此可以经 `r` 修改 `n`。`shared` 又加了一层共享引用，访问过程已经受到限制；继续遇到内部可变引用时，需要保留这个限制。这是本章反复会用到的权限关系。

## 借用与解引用

`let mut` 允许给绑定重新赋值，`&mut T` 允许按相应规则修改所指目标。两者影响不同位置，所以需要分开判断。多层引用则从外往里看，借用位置的 `&&` 也要结合语境理解成嵌套借用。

显式解引用接受引用或 `Box`，找到内部目标后继续保留位置与权限信息。能解开类型，并不免去后面的可写性检查。这里讨论的是当前访问路径，多个借用是否冲突、引用是否仍然有效，还需要更完整的规则。

## 操作符与类型要求

一元负号、布尔取反和整数按位取反各有类型要求。二元运算也要分别看：普通整数算术检查相应整数种类，移位允许的左右组合有所不同，逻辑运算要求 `bool`，比较又有自己的规则。

相等比较还依赖 `PartialEq`，也就是类型提供的相等比较能力。两个值类型相同，仍然需要确认这种比较受支持。带引用的大小比较则继续检查引用层次和内部标量，不能直接照搬函数参数的适配结论。

## 写回与转换

```rust
let mut count: u32 = 0;
count = 1;
count += 2;
let signed = count as i32;
```

赋值从 `count` 得到目标类型 `u32`，把它作为右侧的 `expected`，同时确认 `count` 可写。整个赋值正常结束时得到 `Unit`。复合赋值又叠加了一次运算，要同时检查运算条件与写回要求。上面的整数组合可以说明这条主线，更广范围仍需逐个操作符确认。

`as` 明确请求类型转换，先检查原表达式，再解析目标类型，最后确认组合是否允许。当前支持整数之间和 `bool` 到整数等指定转换，连续转换逐层保留。

**运算决定怎样使用值，赋值与借用还要检查怎样访问这个值。**

本章把 `place`、引用权限与一元访问操作合在一起，再把二元运算、赋值和显式转换连起来。这样看每一个例子时，都可以同时问类型要求来自哪里，以及这条访问路径允许做什么。
