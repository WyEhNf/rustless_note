## 有限布局

字段类型确定后，可以沿着字段检查结构体的组成。对象需要具有有限大小，请求的派生能力也需要字段支持。两项检查使用同一组类型信息，但会沿不同关系继续处理。

```rust
struct Bad { next: Bad }
struct Tree { children: Vec<Tree> }
```

`Bad` 的字段直接放一个完整 `Bad`，里面又需要一个 `Bad`，无法得到有限大小。`Tree` 则先保存 `Vec` 自己的形状，子节点由容器另外组织，因而能隔开这种直接展开。引用和 `Box` 也能在存放关系中起到类似作用。

数组直接保存元素，因此检查会继续进入元素类型。多个结构体相互按值包含，也需要顺着字段判断。走回当前尚未完成的展开路径时，就能发现问题。这里先确认大小能否有限，具体字节数、对齐与字段偏移可以随后再算。

## 字段与派生能力

`derive` 请求根据字段提供某种能力，能力名也叫 `trait`。当前重点是 `Copy`、`Clone`、`PartialEq` 和 `Eq`：`Copy` 允许复制后继续使用原值，`Clone` 支持显式克隆，`PartialEq` 支持相等比较，`Eq` 还要求相等关系具有自反性。

```rust
#[derive(Clone)]
struct Tree {
    children: Vec<Tree>,
    value: i32,
}
```

这个类型的大小可以有限，但 `Clone` 还要检查字段。`Vec` 的 `Clone` 依赖元素，于是继续遇到 `Tree`；当前规则需要处理这种重复路径，同时继续检查 `value` 等其他字段。把请求改成 `Copy`，`Vec` 自身不支持 `Copy`，就无法按这项能力通过。

共享引用则可以支持 `Copy`，它复制的是引用本身。可变引用、`Box`、`Vec` 在当前规则中不支持 `Copy`。数组和结构体还要按组成继续检查。请求 `Copy` 时要显式写 `Clone`，请求 `Eq` 时要显式写 `PartialEq`，重复 `derive` 也会被检查。

## 不同的递归

**遇到递归时，先看沿着什么关系继续处理，再判断这个环意味着什么。**

常量递归问的是求一个值还需要谁，有限大小检查问的是对象内部直接放了谁，能力检查则按具体 `trait` 继续看字段。函数递归发生在运行时，检查调用时只要能依据签名确认参数和结果，就可以继续；它是否终止还需要另外分析。

同样，类型大小有限也不保证具体值容易构造。一个只有 `Box` 指向下一节点的链，如果没有结束形式，还要继续思考怎样建立有限的初始值。`Vec` 的空元素列表就可以为树提供一种结束方式。

## 入口要求

最后确认顶层 `main` 存在，并符合当前要求：没有值参数，没有泛型参数，正常返回 `Unit`。结构体里的关联函数 `Type::main` 有自己的所属类型，不能代替顶层入口。

入口检查是 Pass1 对整份程序的收尾。它与字段检查各有对象：字段决定结构体能否成立，`main` 的签名决定程序能否按约定开始。声明层面的要求确认以后，函数体中的构造、比较和调用就能据此逐项检查。
