## 接收者类型

点号和下标把操作接在一个已有对象后面。这个对象称为接收者。先得到它的类型，才能决定到哪里找方法或字段，以及下标可以取得什么元素。接收者外面若包着引用或 `Box`，访问还会继续经过这些层次。

```rust
struct Point { x: i32 }
impl Point {
    fn read(&self) -> i32 { self.x }
    fn set(&mut self, n: i32) { self.x = n; }
}
let mut p = Point { x: 1 };
p.set(2);
let n = p.read();
```

两次方法调用都先得到 `Point`，再到它的关联成员中查找。找到 `set` 的签名，才知道需要可变接收者；找到 `read`，则知道共享借用已经足够。因此自动解引用与最后补上的借用要分开决定，并按顺序记录。

## 方法与结果

接收者可能来自一个复杂表达式，也可能套着多层引用或 `Box`。查方法时需要留下每一步调整，确定方法后再检查 `self`、显式参数与结果。要求 `&mut self` 的方法还要确认访问路径可写，没有 `self` 的关联函数则用类型关联形式调用。

接收者最终调整成 `&Point`，并不意味着整个调用得到 `&Point`。上面的 `read` 返回 `i32`，调用结果与接收者调整分别记录。内建容器方法还有专门的接收范围，不能由用户结构体上的自动解引用推断所有容器方法都支持任意包裹层。

## 字段与下标

字段访问先根据接收者类型找到字段声明，再取得字段类型和位置性质。下标访问则确认容器是受支持的数组或 `Vec`，索引需要 `usize`，结果得到元素类型和相应位置。

```rust
let mut a = [1, 2];
let r = &mut a;
r[0] = 3;
let s = &r;
s[0] = 4; // 经过共享访问，元素不可写
```

两个索引都可以按 `usize` 检查，差别在到达数组的路径。`r` 提供可变访问，`s` 又增加共享层，因此写入受到限制。数组原本用 `let mut` 声明，并不能替后面每一条访问路径作出相同判断。

## 访问限制的传递

字段或 `Vec` 元素内部可能又存着可变引用。这时仍要保留外面已经留下的共享限制，后续解引用不能仅凭内部的 `mut` 恢复写入。字段、下标与解引用交替出现时，每一步都需要继续传递这项信息。

**最终类型告诉我们找到了什么，访问过程告诉我们现在能怎样使用它。**

连续访问会交替经过方法、字段、下标与解引用。每一步都依据当前结果继续查找，同时保留已经形成的访问限制。类型与权限检查通过，也仍需要把运行时下标越界、多个借用之间的冲突等问题放在各自的范围中判断。
