## 支持的写法

常量求值处理一组明确的表达式：字面量、允许的取负、括号和常量路径。表达式是否在这个范围里，需要根据写法判断，无法只凭结果容易算出就决定。

```rust
const N: usize = 0x10usize;
const FLAG: bool = true;
const NEG: i32 = -3;
const M: usize = N;
```

`N` 先按后缀确定 `usize`，再把十六进制文本读成 16。`FLAG` 是 `bool`，`NEG` 对有符号整数取负，`M` 通过名字引用 `N`。括号用于分组，例如 `(N)` 可以继续得到 `N` 的值。关联常量中的 `Self` 需要先换成当前所属类型。负号不能任意套在无符号整数上。`const BAD: u32 = -3;` 不满足这里的取负要求。

如果在常量名字后面多写一个加法，检查需要的能力就变了。不能仅凭结果看起来容易计算，就认定当前规则已经支持。

```rust
const N: usize = 3;
const SAME: usize = N;
const NEXT: usize = N + 1; // 当前常量范围不支持
```

`SAME` 只引用已有常量，可以沿依赖求值。`NEXT` 多了二元加法，当前受限常量规则没有包括这类任意运算。同样，调用普通函数也不能自动进入常量求值。完整语言可以扩展这些能力，但需要额外规则。求常量时仍然会检查涉及的表达式并保存结论，所以表达式记录可能在第一阶段就产生。

## 长度的要求

固定长度数组的**元素数量属于类型**。两个长度写成不同的常量名字，最后却可能得到相同的数组类型。

```rust
const A: usize = 3;
const B: usize = 3;
let x: [i32; A] = [0; B];
let y: [i32; 4] = [0; A]; // 长度不符
```

`A` 与 `B` 的名字不同，求值后都是 3，因此 `x` 的声明类型与初值长度一致。`y` 要求 4 个元素，初值只有 3 个。比较数组类型时，需要比较求值后的长度，而无须要求源码中的常量名字相同。确定长度还帮助后面计算对象大小。具体占多少字节、字段放在哪里，可以在之后继续处理。

为了得到这个长度，还要检查长度位置接受的写法和类型要求。它和运行时的下标访问虽然都用方括号，承担的作用不同。

```rust
const N: usize = 3;
let a: [i32; (N)] = [0; 3];
let b: [i32; 3i32]; // 错误：长度类型应为 usize
```

`a` 的外围括号可以去掉，找到 `N` 后确认其类型和值，再得到长度 3。直接数字可以不写后缀，也可以写 `usize`。`Self::N` 需要先按所属类型换成完整关联名，然后同样检查常量类型与值。类型里的 `[i32; N]` 决定元素数量；值上的 `a[N]` 选择一个元素。这两个位置虽然都出现 `N`，检查目的不同。

遇到直接写出的数字时，也要把整个文本读完。进制前缀、分隔下划线和类型后缀都可能影响处理方式。

```text
1_024  → 1024
0xff   → 255
0o10   → 8
0b101  → 5
12abc  → 失败
```

下划线方便阅读，可以先去掉。`0x`、`0o`、`0b` 分别指定十六、八、二进制；没有前缀时按十进制处理。`12abc` 即使前面的 `12` 可以读取，后面的 `abc` 仍然没有合法意义，不能只保留 12 就宣布成功。类型后缀先由相应语境处理。普通整数字面量与数组长度共享读取数字的能力，但之后还要满足各自的类型及范围要求。

## 结果的解释

求出值以后，也还需要保留类型。相同的一串位，按有符号整数和无符号整数解释，会得到不同数值。

```rust
const NEG: i32 = -1;
const MAX: u32 = 0xffffffffu32;
```

在 32 位表示下，两者的位都可以是 `0xffffffff`。按 `i32` 解释为 -1，按 `u32` 解释为 4294967295。因此常量结果需要能找到所属声明及其类型。只看一个无符号位容器，就会丢掉有符号解释。求值过程中可以使用更宽的整数暂存结果，确认规则与范围后，再保存面向目标的 32 位表示。
