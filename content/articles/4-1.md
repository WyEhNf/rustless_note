## Block：顺序与结果

**`Block` 是块表达式，`Stmt` 是块中的语句。**

函数体是一个块，块里按顺序放着语句。语句又会包含表达式，所以从块走到表达式之后，还可能继续遇到更小的块。

```rust
fn add_one(x: i32) -> i32 {
    ;
    let y = x + 1;
    y
}
```

第一行分号是空语句。`let` 引入 `y`，其初值是加法。最后的 `y` 是没有分号的**尾表达式**，给整个块提供结果。尾表达式也可以放在语句列表中，通过“最后一项”和“没有分号”来识别。无需把每种文法名称都变成独立节点类别。块内部还能出现另一个块，后者继续包含语句。递归关系因此可以不断向下延伸。

块末尾是否带分号，会影响它给外面提供什么结果。只改这一处，就能看到表达式语句与尾表达式的差别。

```rust
let a = { 1 };
let b = { 1; };
```

`a` 得到整数 1。`b` 的块计算过 1，但分号丢弃了这个值；块正常结束后得到 `Unit`，也就是 `()`。若函数声明返回 `i32`，函数体只有 `{ 1; }`，结果类型就对不上。删掉这个分号以后，整数才作为函数体的尾值。带块的表达式在某些语句位置可以省略分号，还要结合所处位置理解。不能把所有“没有分号”的片段都机械地当成函数返回值。

### Stmt：语句与绑定

`let` 也会包含初值表达式，不过它还承担引入名字的工作。因此建树时要一起留下名字、是否可变、可选的类型标注和初值。

```rust
let mut count: i32 = 0;
count = count + 1;
let count = count + 1;
```

第一行明确 `count` 的类型，并允许重新赋值。第三行再次使用 `let`，产生新的绑定，右边仍需要读取此前可见的 `count`。这种同名新绑定叫遮蔽，或 `shadowing`。新名字生效的时间会影响初值查找，后面会单独讨论。

当前局部绑定只处理单个名字。`let (x, y) = pair;` 这样的拆分绑定还需要保存模式，即值的各个部分与名字怎样对应；本文暂不展开这种写法。

## Primary：表达式的起点

在文法里，`Primary` 表示可以继续接上运算的基本写法。字面量很简单，括号里面却能放复杂表达式，所以“基本”要结合这一层文法来理解。

```rust
1
x
(x + 1) * 2
```

整数 1 和名字 `x` 可以直接成为基本节点。第三行的 `(x + 1)` 也能作为乘法左侧的起点，但其中仍然包含加法及两个孩子。括号本身可以在 AST 中省去，因为加法处于乘法左子树这一关系已经保留了分组。因此树的**最终叶子**通常是字面量或名字等基本内容；`Primary` 的文法范围则可以比叶子更宽。

表达式的范围还包括数组、块和跳转。它们能出现在什么位置，要继续看各自的规则。

```rust
struct Point { x: i32 }
fn value() -> i32 {
    let p = Point { x: 1 };
    let a = [1, 2];
    return p.x + a[0];
}
```

结构体构造同时保存字段名 `x` 和值 1。数组保存两个元素。`return` 携带的内容是一整棵加法，左右两侧又分别是字段访问与下标访问。写成 `return;` 时，没有显式携带值，后面按 `Unit` 理解。写成 `return p.x;` 时，则要继续检查字段访问。字段的名字和所在位置也需要留下，这样重复字段或未知字段才能指出具体写错的位置。

尤其是 `if` 和 `while` 的条件后面都紧跟大括号；大括号既能组织块，也能跟在结构体名字后写字段值。读取时需要结合周围的写法判断。

```rust
if flag { work(); }
// 完整 Rust 中，可用括号明确结构体构造：
if (Check { ok: true }).ok { work(); }
```

第一行的 `flag` 是条件，后面的大括号属于 `then` 分支。若把它继续当作条件内的结构体构造，就会读错边界。第二行先用括号包住构造式，再取 `ok` 字段。括号明确了这部分属于条件表达式，最后一对大括号才开始分支体。因此普通表达式位置和条件位置可以采用不同的文法规则。建树仍要把它们整理成对应的表达式结构，条件类型则在后面检查。
