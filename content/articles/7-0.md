## 类型和值

常量声明给出类型和初值，这一章把两者之间的关系展开。声明类型说明结果应该怎样解释，编译期求值则给出具体结果。它们需要分别检查、分别记录进度，有依赖时又需要配合。

```rust
const A: usize = B;
const B: usize = 3;
struct Row { data: [i32; A] }
```

求 `A` 时先找到 `B`，`B` 的初值得到 3，于是 `A` 也得到 3。解析 `Row` 的字段时，仅知道 `A` 是 `usize` 还不够，还需要这个具体数值，才能确定完整的数组类型为 `[i32; 3]`。所以类型解析有时会提前请求常量求值，再回到原来的类型继续处理。

名字使用也要留下所关联的常量声明。这样后面看到 `A` 的值时，可以同时知道它来自谁、属于什么类型。即使某条常量没有被函数使用，也应检查它自己的声明与初值。

## 依赖与求值顺序

求值会沿着常量引用继续向下，可以用深度优先的方式处理：先沿当前依赖走到底，完成后回到上一层。记录尚未开始、正在处理、已经完成和已经失败，就能区分正常复用与循环依赖。

```rust
const A: usize = B;
const B: usize = A;
```

进入 `A` 后又进入 `B`，`B` 再次请求尚未完成的 `A`，这条依赖就回到了起点。已经独立算完的常量被多处使用则可以直接复用。数组长度还可能把类型解析和值求解连成更复杂的环，因此两类进度需要分开记录。

失败状态也要保留。后面为了继续查看其他问题，可能留下临时记录，但这些记录不能消除已经发现的循环依赖。

## 常量表达式的范围

当前常量求值处理一组明确的写法，包括整数、布尔值、允许的取负、括号和常量路径。关联常量中的 `Self` 先根据所属类型展开。普通函数调用和任意二元运算没有自动包含在这个范围里，因此能引用 `N`，还不能直接推出 `N + 1` 也受支持。

本章会把数组类型中的长度与值上的下标分开讨论。`[i32; N]` 需要在编译期确定类型里的元素数量，`a[N]` 则在使用处选择一个元素。长度写成常量名时要确认类型和值，写成数字时还要完整处理进制、下划线、后缀和剩余字符。

## 数值与类型

**数组类型比较的是求值后的长度，常量结果则始终需要结合类型理解。**

不同名字都求得 3，可以形成相同长度；相同位表示按 `i32` 与 `u32` 解释，却可能对应不同数值。这里按 32 位目标讨论，还要留意暂存值与最终范围的关系。

本章先把依赖、提前求值和循环判断连起来，再看支持的表达式、数组长度及数值表示。AST 只需保留有限的源码结构，常量之间的依赖环则是在名字查找和求值时发现的，这也说明两类工作的分工。
