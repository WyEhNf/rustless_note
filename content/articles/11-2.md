## 数组的组成

数组要同时确定元素类型和长度。外层已经给出数组类型作为 `expected` 时，可以把元素要求交给每个孩子；缺少要求时，再尝试根据元素得到共同类型。

```rust
let a: [u32; 3] = [1, 2, 3];
let b: [i32; 2] = [1, 2, 3]; // 长度不符
let c = [1, true]; // 元素类型不符
```

`a` 的三个数字分别得到 `u32` 期望，长度也等于 3。`b` 的元素类型正确，但多了一个元素。`c` 则无法把整数与 `bool` 合成这里支持的共同类型。引用元素还可能通过适配找到共同类型。当前处理从首个元素开始更新，并没有完整回头补齐所有较早元素的调整。因此复杂的引用混合数组不能只按理想化的共同类型规则推断所有细节都已完成。

空数组没有元素可供推导，这时上下文就尤其重要。但补上元素类型，并不会改变它实际包含零个元素的事实。

```rust
let a: [i32; 0] = [];
let b = []; // 缺少元素类型
let c: [i32; 1] = []; // 长度不符
```

`a` 从标注取得 `i32`，而空数组实际长度为 0，二者一致。`b` 没有任何元素也没有标注，缺少确定元素类型的依据。`c` 虽然提供 `i32`，却要求一个元素。空数组仍然只有零个元素，外层 `let` 会继续发现长度不匹配。元素类型与长度都是数组类型的一部分，提供其中一项不能代替另一项。

重复写法还多了一个问题：同一个值需要使用多少次。**次数必须能够在编译期确定**，多次使用时也要考虑元素能否 `Copy`。

```rust
const N: usize = 3;
let a = [7; N];
let b = [Box::<i32>::new(1); 1];
let c = [Box::<i32>::new(1); 2]; // 不支持 Copy
```

`a` 的次数是 `usize` 常量，整数支持 `Copy`。`b` 只使用一次 `Box` 值，不触发多次复制要求。`c` 需要重复两次，`Box` 不支持 `Copy`，因而被拒绝。次数为零或一时，不触发这条 `Copy` 检查。次数本身仍要符合受支持的常量范围。局部 `let n = 3` 即使看起来固定，也不能直接充当这里要求的命名常量。

## 字段的要求

构造结构体时，先确定要构造哪个类型。字段声明随后给出每个初值的 `expected`，所以同一组初值可以分别接受不同要求。

```rust
struct Point { x: i32, y: u32 }
let p = Point { x: 1, y: 2 };
```

`x` 的初值按 `i32` 检查，`y` 的初值按 `u32` 检查。同样写成无后缀整数，可以根据各自字段要求得到不同类型。构造式整体得到 `Point` 类型，是新产生的值，并可以关联到 `Point` 的声明身份。方法中的 `Self { ... }` 先根据所属类型确定具体结构体，再执行同样的字段检查。

**字段的名字和内容**都需要检查。名字齐全不保证值的类型正确，值看起来合理也不能补上缺失或拼错的字段。

```rust
struct Point { x: i32, y: i32 }
Point { x: 1, z: missing }; // z 未知、y 缺失、missing 未定义
Point { x: 1, x: 2, y: 3 }; // x 重复
Point { x: true, y: 2 }; // x 的值类型错误
```

第一行构造写了不存在的 `z`，同时没有给 `y` 初值。继续检查 `z` 的值，还能发现 `missing` 没有声明。第二个构造的两个 `x` 不能靠“后面的覆盖前面的”当作合法写法。第三个构造字段名字齐全，但 `bool` 不能满足 `i32`。把这些检查分别做完，才能同时说明字段结构与字段内容是否成立。
