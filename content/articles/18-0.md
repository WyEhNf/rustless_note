## 矩阵计算的讨论范围

这一章保留原对话中另外出现的矩阵乘法讨论。它主要关心矩阵怎样存进一维数组、访问方式怎样影响计算，以及删去注释后还需要说明哪些前提。阅读它不依赖前面某个 AST 节点的项目实现。

原题把 `n` 固定为 1024，函数接收 `a`、`b`、`c` 和 `n`，并希望以头文件形式提供。理解后续优化前，先明确每个下标对应哪一行、哪一列，以及结果究竟在累加什么。

## 行主序与矩阵下标

矩阵按行连续存放时，第 `i` 行第 `j` 列的位置是 `i*n+j`。结果矩阵的一个元素，需要把 `A` 的第 `i` 行与 `B` 的第 `j` 列逐项相乘，再加起来。

```cpp
// 用 2×2 的小例子说明下标
const int n = 2;
int a[4] = {1, 2, 3, 4};
int b[4] = {5, 6, 7, 8};
int c[4] = {};
for (int i = 0; i < n; ++i)
    for (int j = 0; j < n; ++j)
        for (int k = 0; k < n; ++k)
            c[i*n+j] += a[i*n+k] * b[k*n+j];
```

计算 `c` 的第一项时，读取 `A` 的 1、2 和 `B` 的 5、7，得到 `1*5 + 2*7 = 19`。`k` 增加时，`A` 的访问连续，`B` 的访问却每次跨一整行。这就说明为什么后面会考虑转置 `B`，让参与点积的两组数都能连续读取。

## 转置与向量运算

转置改变读取顺序，分块让一部分数据更集中地重复使用，向量计算一次处理多项，循环展开则减少部分循环控制。它们各有目的，需要先保证下标和求和结果仍然正确，再考虑性能。

原讨论使用 64×64 小块转置，点积每次处理 16 项，分成两组向量累加后合并。对齐方式影响指令怎样读取和写入，临时数组也要满足对应要求。这里的整数乘法保留低 32 位，加法另行执行；浮点 FMA 属于另一种操作。

分块乘法和 OpenMP 在讨论中属于进一步选择，原代码没有实际加入。是否更快要看数据、机器和测量结果，不能只根据采用了某种写法就保证加速幅度。

## 整数运算与使用前提

**优化与删注释都需要保持计算含义，同时保留适用条件。**

固定 1024 可以被原来的步长和块大小整除，换成其他 `n` 就需要处理尾部。AVX2 要求运行环境支持，静态临时矩阵有容量与并发使用限制，输入输出能否重叠也要约定。整数结果是否可表示，同样需要结合数据范围判断。

无注释版本要核对循环边界、下标、步长、累加与最终求和是否一致。向量低 32 位运算也不能推广成普通 C++ 有符号溢出的保证。本章把原理、优化和无注释版本整合到同一节，按照这些具体问题逐项分析。
