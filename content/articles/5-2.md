## 全局登记表

**全局登记表按名字找到全局声明，供各个函数共同使用。**

它逐步记下声明身份、类型和所属关系，在本次语义分析过程中一直保留。

```rust
struct Point { x: i32 }
const LIMIT: i32 = 10;
fn larger(x: i32) -> bool { x > LIMIT }
```

`Point` 的记录需要包含字段类型及字段身份；`LIMIT` 的记录需要声明类型、求值进度与结果；`larger` 的记录需要参数类型和结果类型。关联成员还要知道所属类型，例如 `Point::get`。这些名字在检查某个函数体结束后仍然存在。因此全局表与进入块后临时增加的局部表要分开。全局声明准备好了，各个函数体才有共同的查找依据。

## scope 符号表

**`scope` 符号表保存当前作用域里的局部名字和绑定。**

进入函数体以后，局部名字开始按块变化。退出内层时，查找范围也跟着恢复。

```rust
let x = 1;
{
    let x = true;
    let only_here = 3;
}
let y = x;
let z = only_here; // 错误
```

退出内层后，`y` 的 `x` 恢复为外层整数。`only_here` 只存在于内层，所以 `z` 找不到它。每层保存名字、类型、`mut` 与声明编号。查找从内往外，找到第一条匹配就停止。弹出局部表不代表抹掉已经记下的检查结果。内层表达式已经绑定到哪个声明，可以继续按节点编号保存。

## 表达式事实表

**表达式事实表按 `NodeID` 保存每个表达式的类型、`place`、写权限和关联声明。**

查找用的局部表可以退出，已经查到的结果却还会继续使用。因此还需要按节点编号单独保存这些结果。

```rust
let x: i32 = 1;
let a = x;
let b = x;
```

`a` 与 `b` 的初值虽然都写 `x`，仍是两次独立出现。分别记录后，就能知道每个位置都指向相同声明并具有 `i32` 类型。类型标注 `i32` 也有自己的语法节点，需要留下它解析成什么语义类型。表达式结果表与类型解析表回答的是两类问题。这种记录不会因为离开局部作用域就消失，后面处理程序时还可以直接按节点取用。

**局部查找范围会退出，已经确认的节点结果仍然可以保留。**

## NodeID 与 SymbolID

**`NodeID` 表示语法节点的这一次出现，`SymbolID` 表示声明的身份。**

一个声明可以在多处被使用，每处使用都有自己的节点编号。把这两个身份分开后，就能说明 `x + x` 中两个 `x` 的共同点和区别。

```rust
let x = 1;
let z = x + x;
```

可以假设声明 `x` 的编号是 10，左右使用点分别是 12 和 13。它们都指向声明 10，加法另有自己的编号 14。加法的整体结果是整数，不必另外宣称它直接绑定了 `x`。需要了解参与计算的声明时，继续查看两个孩子即可。因此一个节点可以没有直接关联声明，也可以保存一条直接关联声明；同一声明可以被多个节点引用。

### owner：声明的所属关系

除了“指向谁”，有时还需要知道“属于谁”。字段属于结构体，参数属于函数，关联方法也有所属类型，这个关系称为 `owner`。

```rust
struct Point { x: i32 }
impl Point {
    fn add(&self, value: i32) -> i32 { self.x + value }
}
```

`x` 字段与 `add` 方法属于 `Point`；`value` 参数属于 `add`。这样同样叫 `value` 的参数也能按所属函数区分。解析 `Self` 时需要知道当前所属结构体，所以可以根据 `Point` 这个关系解释 `Self`。

记录声明关系时则可以使用编号，避免仅凭文字混淆。`self` 是特殊的接收者绑定。这里可以复用所属方法的身份，不要求它与普通参数一样拥有单独的参数节点。

编号便于留下这种关系，检查过程中也可以直接找到对应记录。两种方式都在帮助理解程序，不必与运行时的存储地址混在一起。

```rust
fn f(x: i32) -> i32 { x + 1 }
```

检查函数体时，可以直接找到 `f` 的记录，读取它要求的返回类型。检查 `x` 时，则记住它对应哪个参数声明。这个编号或对象连接属于编译器分析程序时使用的信息。`x` 最后放在寄存器、栈上，还是被优化掉，要到后面才决定。离开 `f` 的检查后，当前函数这一临时上下文可以清空，而已经记录的节点与声明关系继续保留。

## 类型解析表

**类型解析表把类型语法节点的 `NodeID` 对应到已经确定的语义类型。**

语义类型已经解析了源码中的名字与长度。比较两个类型时，就可以逐层看引用可变性、数组长度、元素类型和声明身份。

```rust
let a: &[i32; 3];
let b: &[i32; 3];
let c: &mut [i32; 3];
```

`a` 与 `b` 都是共享引用，内部数组长度和元素类型也一致，因此类型相同。`c` 的引用可变性不同，需要进一步按适配规则判断能否使用。数组比较长度和元素；`Box`、`Vec` 比较元素；结构体与函数要确认具体身份。

创建一个类型描述，只是把这些信息组织起来，名字是否合法仍要查表。`Error` 可以在出错后的比较中临时视作兼容，目的是继续发现独立问题。它不使原程序变成合法程序。

### 子表达式与整体结果

即使孩子的类型已经清楚，**父表达式也需要产生自己的结果**。特别是 `place` 和写权限，不能直接照抄某个孩子的性质。

```rust
let mut x = 1;
let y = x + 1;
```

`x` 是可写位置，整数 1 是直接的值。整个 `x + 1` 得到 `i32`，但它没有因为左孩子可写，就变成可以赋值的位置。检查加法时先得到孩子的结论，再按加法规则产生整体结论。之后还要应用上下文允许的调整，并按当前节点保存结果。字段访问和下标访问可能产生 `place`；函数调用通常还要记录调用目标。各种形式都需要根据自身规则决定这些属性。

### 常量结果与其他记录

把这样的结论按各自用途保存下来，后续就能同时找到声明、类型、常量值以及表达式的使用方式。

```rust
const N: usize = 3;
fn main() {
    let a: [i32; N] = [0; N];
}
```

声明记录说明 `N` 是哪个常量；类型记录说明数组长度已解析为 3；常量记录保存 `N` 的值；表达式记录说明初值的类型与所引用的声明。隐式借用等调整包含在相应表达式结论中。合法性错误另外保存，不能因为某张结果表里有内容就认为程序通过检查。把类型打印成 `[i32; 3]` 便于阅读。后面真正使用类型时，仍可以直接读它的元素与长度等内容。
