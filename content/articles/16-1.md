## 几类记录

检查结束后，会留下几类相互配合的信息。声明说明程序中有哪些对象，表达式记录说明某次使用指向谁、得到什么类型以及怎样访问。

```rust
let mut p = Point { x: 1 };
let a = p.x;
let b = p.read();
```

`p` 的声明记录说明它属于当前函数。`p.x` 的表达式记录指向字段声明，`p.read`() 的记录指向方法声明；这些使用点还有各自的节点编号。表达式还保存类型、`place`、可写性、访问限制和调整。顶层、字段及关联成员主要在第一阶段登记，参数和局部变量在第二阶段补充。常量求值也会产生表达式记录，因此不能把所有表达式结论都归为只在第二阶段出现。

类型解析和常量求值也相互联系。数组长度一旦确定，后面使用语义类型时就能直接取得这个结果。

```rust
const N: usize = 2;
let a: [i32; N] = [0; N];
let b = 1i32 as u32;
```

`a` 的类型节点解析成元素为 `i32`、长度为 2 的数组；`N` 的结果另按常量声明身份保存。后面使用数组类型时，无须再次按名字算一遍 `N`。`b` 的转换目标 `u32` 也需要类型解析记录。声明类型主要在第一阶段处理，局部标注、`cast` 目标与容器类型实参还会在第二阶段出现。常量位表示需要结合对应类型解释，不能脱离声明只看一串位。

最后整理记录时，要保留**各自编号与分类的含义**。它们方便后续使用，但是否存在错误仍然需要单独判断。

```rust
const N: usize = 2;
fn f(x: i32) -> i32 { x }
fn main() { let y = f(1); }
```

可以按声明编号列出 `N`、`f`、`main` 以及参数和局部绑定；表达式和类型结果按各自节点编号整理。完成求值的常量再按声明编号列出。顶层函数、结构体和常量数量，与关联成员数量需要区分。一个类型中的方法不应无声地混进“顶层函数数”的含义里。转移已经收集好的记录可以减少复制，但不会重新决定类型。是否存在错误仍然单独判断。

## 树与结果

AST 告诉我们一个表达式包含哪些孩子，语义结果则说明它们指向谁、满足什么类型要求。后续处理程序时，两部分信息需要一起使用。

```rust
fn read(x: &i32) {}
let b = Box::<i32>::new(1);
read(&b);
```

AST 说明这是一处调用，实参是对 `b` 的借用。语义结果说明目标是 `read`，实参原型为 `&Box<i32>`，并需要解引用后重新借用成 `&i32`。只有树，后面还得重新查名字和适配规则；只有类型列表，又不知道调用和借用怎样嵌套。把额外结论按节点存放在独立表中，可以保留原树，同时让后面直接取用已经确认的含义。

**AST 保留结构，语义记录补上已经确认的含义。**

为了阅读方便，可以把其中一部分打印出来。不过，一份打印文本选择展示哪些信息，也会限制我们能从中看出什么。

```rust
const N: usize = 2;
let a: [i32; N] = [0; N];
```

看到 `a` 的表达式类型 `[i32; 2]`，可以理解长度已经确定；但若输出只列声明与表达式，就未必单独展示 `N` 的常量位值和每个类型节点的记录。当前结果打印偏重摘要、声明和表达式，没有把所有类型解析及常量集合逐项列出。因此用文本检查某项性质时，先确认这份文本有没有打算显示它。格式化的类型名称主要帮助人阅读，内部仍可以保留结构化内容。
