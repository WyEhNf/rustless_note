## 词与语法树

程序文本由字符组成，声明与运算的边界还需要读出来。词法分析认出词，语法分析确定分组，建树再把这些分组整理成后面可以直接使用的节点。

负责认词的部分叫 `Lexer`，也就是词法分析器。它把名字、数字、操作符等读成 `token`，可以先理解成一个个词。`Parser` 是语法分析器，它根据文法判断这些词怎样组成声明、语句和表达式。文法说明允许怎样写，`ANTLR` 可以根据 `.g4` 文件中的文法生成这两个分析器。

```rust
fn main() {
    let answer = 1 + 2 * 3;
}
```

读这段程序时，先认出 `fn`、`main`、`let`、`answer` 和几个数字、符号。接着知道 `main` 是函数，花括号里面是函数体，`let` 引入 `answer`，等号右边是它的初值。初值中乘法先组成一部分，再与 1 相加。这些层次会进入具体语法树 CST。

## CST 与 AST

CST 保留了文法规则之间的嵌套。里面表示一个已识别语法片段的对象称为 `Context`；有的孩子还能继续展开，有的已经是具体的词。整理时沿着这些孩子递归往下走，读取每一段真正需要的内容。

AST 叫抽象语法树，它留下程序的主要结构。上面的初值可以表示成一个加法节点，左边是 1，右边是一整棵乘法子树。这里节点就是树中的一个对象，下一层相连的节点叫孩子。文法中只负责包装、没有新增操作的层次，可以在整理时省去。

**分组已经由父子关系表达出来，后面才能沿着树继续理解程序。**

## 结构与语义

树还要留下名字、源码位置和每次出现的编号。名字供后面查找声明；位置帮助指出错误发生在哪一段；编号则区分两个看起来相同的使用点。数字的原文也有用，例如 `0xffu32` 同时说明进制和类型后缀。

这些节点可以按层次打印出来。打印出来的缩进帮助我们观察父子关系，后续检查实际使用的是节点之间的连接。改变缩进不会改变运算，改变父子关系则可能改变含义。

## 输入检查的范围

完整检查需要读到输入结束。只认出前面的 `1`，还不能忽略后面多出来的 `2`；未闭合的注释也可能到文件末尾才被发现。检查表达式、类型或整份程序时，还需要选择相应入口。

```rust
let a = 1 + true; // 结构完整，后续类型检查会发现问题
let b = 1 + ;    // 缺少右操作数，语法不完整
```

这两行说明建树与语义检查各自负责什么。前一行能够组成加法结构，后一行连完整结构都缺少。这一区别也决定错误发生后可以继续做什么：缺少右操作数时，正常结构尚未形成；结构完整而类型不合适时，已有节点和源码范围可以帮助后续检查准确指出问题。
