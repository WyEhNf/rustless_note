## 输入输出

有些函数直接由当前语言的内建规则认识。检查输入输出调用时，先确认它们的参数和结果类型，实际读写则留到运行时。

```rust
let n = getInt();
printInt(n);
printlnInt(42);
printlnInt(true); // 错误：需要 i32
```

`getInt` 不接收值参数，返回 `i32`。`printInt` 与 `printlnInt` 各接收一个 `i32`，返回 `Unit`；后者还换行。这里还有 `get_i32`、`print_i32`、`println_i32` 兼容名字，分别对应相同的类型要求。

这些兼容名字的识别与[内建名字保护](/posts/6.1)各有范围。实际读写发生在程序运行时，当前先按上述签名确认传值与结果。

内建规则也解释了为什么有些调用可以带类型实参。用户函数是否支持泛型，仍需要看声明和相应的检查能力。

```rust
fn f() {}
f::<i32>(); // 当前用户函数不支持类型实参
let v = Vec::<i32>::new();
```

`f` 是普通用户函数，当前没有相应**类型参数支持**，因此不能因为调用处写了 `i32` 就接受它。`Box` 与 `Vec` 走专门的内建规则，允许使用明确的元素类型实参。语法树可以保存某些参数名，调用是否受支持仍由这组具体规则决定。

## 容器操作

`Box` 和 `Vec` 通过内建规则使用元素类型。构造时既要检查类型实参，也要检查有没有提供正确数量和类型的值。

```rust
let b = Box::<i32>::new(7);
let v = Vec::<i32>::new();
let bad = Box::<i32>::new(true); // 类型不符
```

`b` 的类型实参指定 `i32`，值实参 7 按 `i32` 检查，结果是 `Box<i32>`。`v` 没有元素初值，结果是 `Vec<i32>`。`bad` 虽然类型实参正确，实际值仍是 `bool`，无法满足要求。`Box::new` 的值参数数量也必须为一，`Vec::new` 则为零。当前规则要求**显式类型实参**，不能仅凭外部标注就省掉这里的 `i32`。

构造完成后，还可以通过关联形式使用容器操作。每个操作接收什么引用、是否需要写入、返回什么，都分别规定。

```rust
let mut v = Vec::<i32>::new();
Vec::<i32>::push(&mut v, 7);
let n = Vec::<i32>::len(&v);
let empty = Vec::<i32>::is_empty(&v);
let x = Vec::<i32>::remove(&mut v, 0usize);
```

`push` 接收可变 `Vec` 引用和一个元素，结果为 `Unit`。`len` 接收共享引用，返回 `usize`；`is_empty` 返回 `bool`；`remove` 接收可变引用与 `usize` 下标，返回元素。`Vec::clone` 接收共享 `Vec` 引用，返回同类型 `Vec`。`Box::clone` 类似，但返回 `Box`；两者都需要检查 `Clone` 能力。

候选名字可能比实际支持的组合宽。不能把 `Vec` 的某个操作直接套到 `Box` 上，就推断一定有效。

`clone` 还涉及能力检查。点调用与显式关联调用在当前规则中存在差别，这个边界需要结合具体写法来看。

```rust
#[derive(Clone)]
struct S { x: i32 }
let s = S { x: 1 };
let a = S::clone(&s);
let b = s.clone();
```

从语言含义看，两种写法都在克隆 `s`。当前点调用会检查接收者是否支持 `Clone`。显式结构体 `clone` 候选可以得到“接收 `&S`、返回 `S`”的要求，但该路径没有执行与点调用完全相同的能力判断。因此上面选用确实声明 `Clone` 的 `S`。若去掉 `derive`，不能把某条路径仍被接受解释成类型已经正确具备克隆能力。


## 检查与实际执行

容器接口的类型要求，可以在执行程序之前确定。沿用上面的 `v`，连续两次添加元素仍然使用同一个 `push` 签名。

```rust
v.push(7);
v.push(8);
let n = v.len();
```

检查时，两次 `push` 都要求可写接收者和 `i32` 元素，正常结果为 `Unit`；`len` 只需读取接收者，结果为 `usize`。只允许共享访问时，`len` 可以成立，`push` 会因接收者要求失败。

程序运行到 `push`，才实际查看容量、按需申请存储、放入元素并更新长度。这些动作可以由生成的代码或随程序运行的支持代码完成，也可以由库提供。语义分析在这里保留目标、类型与必要调整，容器存储的具体处理留在这项工作之后。
