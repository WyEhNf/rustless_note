## scope：进入与退出

进入内层块，就增加一层名字查找范围；退出后，这一层不再参与后续查找。即使前后都写 `x`，每次使用也可能指向不同声明。

```rust
let x = 1;
{
    let x = true;
    let y = x;
}
let z = x;
```

`y` 的初值指向内层 `x`，类型是 `bool`。`z` 的初值指向外层 `x`，类型是 `i32`。内层表退出后，不再参加后面的名字查找，但 `y` 那次使用已经找到谁，可以继续按节点保存。因此后面处理整个程序时，无须重新猜每个 `x` 当时处在哪一层。[节点结果记录](/posts/5.2)保留了这次查找的结论。这里作用域表的变化，只影响后面还未检查的名字使用。

每层的名字对应一个绑定记录，也称为 `Binding`。用哈希表或按名字排列的表保存这些记录，都需要遵守从内向外的查找顺序；表的存放方式不会改变作用域规则。

### 同名新绑定

同一个块里再次声明同名 `let`，称为遮蔽（`shadowing`）。新名字的生效时间会直接影响它自己右边的初值。

```rust
let x = 1;
let x = x + 1;
let y = x;
```

第二行右侧 `x` 找到第一行声明，因此算的是旧值加一。第二行检查完以后，`y` 再找到新的 `x`。若一开始就写 `let x = x + 1;`，此前没有 `x`，右侧应报告找不到名字。

为了继续检查后面的程序，可以用 `Error` 暂时表示出错后无法确定的类型，并登记一个带这种类型的新绑定。它供后续检查继续进行，原来的错误仍然保留。因此先检查初值说明查找顺序，失败后也可能留下临时记录。

**`let` 的初值先使用此前可见的名字，新绑定随后才生效。**

`let` 检查完以后，绑定的类型也随之确定。当前这套推导规则不会因为后面某次使用提出了新要求，就回头改写先前的结果。

```rust
fn take(x: u32) {}
let a: u32 = 1;
let b = 1;
take(a);
take(b); // 当前规则下类型不匹配
```

`a` 的标注给整数 1 提供 `u32` 期望。`b` 没有标注，整数按默认规则取 `i32`。调用 `take` 时，`a` 满足签名；`b` 已经是 `i32`，不会因为函数需要 `u32` 就回头修改前面 `let` 的推导。可以明确写 `let b = 1u32;`，也可以在使用时按支持的规则显式转换。这与完整语言更广泛的推导能力要区分。

## 循环栈与当前函数

检查器走进一个块时，可能同时处在多层表达式和多层循环里。虽然都能画成一层套一层，它们各自回答的问题仍然不同。

```rust
loop {
    let x = 1;
    if x > 0 {
        loop { break; }
        break;
    }
}
```

作用域记录 `x` 在哪里可见；递归检查过程记录当前正在处理 `if`、比较还是块；循环栈则指出 `break` 的目标。第一个 `break` 对应内层 `loop`。内层结束后，第二个 `break` 对应外层 `loop`。`if` 会把类型结论返回给父节点，却无需成为独立循环跳转目标。循环记录还要收集 `break` 携带值及期望结果，这些内容放进名字表并不合适。

因此检查某个表达式时，具体要用哪份上下文，要看它正在做什么。查名字、`return` 和 `continue` 分别需要不同信息。

```rust
fn f() -> i32 {
    loop {
        let x = 1;
        if x > 0 { return x; }
        continue;
    }
}
```

`x` 的使用需要作用域，`return` 需要当前函数的 `i32` 结果要求，`continue` 需要当前循环。加法或比较还会递归检查自己的孩子，并可能对子表达式提出类型要求。无需把每次表达式检查都理解成寻找循环。完整 Rust 的带标签跳转还需要记录标签与对应循环。当前循环记录没有这项信息，因此这里只讨论最近的可用循环。
