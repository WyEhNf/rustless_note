## 有限大小

结构体对象需要能够用有限的存储表示。如果一个字段直接放着同一种结构体，就还需要继续展开它自己的全部字段。

```rust
struct A { next: A } // 无限展开
struct B { next: [B; 1] } // 同样无限展开
```

`A` 中放一个完整 `A`，里面还要再放 `A`，因而无法得到有限大小。`B` 的数组直接保存元素，也继续要求一个完整 `B`。两个结构体互相按值包含同样会成环。当前检查沿数组元素继续判断，即使数组长度写成 0，也没有把这一分支特殊跳过。布局说的是对象组成如何占用存储。这里先确认能否有限形成，之后才计算具体大小。

如果通过引用、`Box` 或 `Vec` 接到下一个对象，存放关系就有了变化。不过，类型大小有限和具体值能够结束，还需要分开考虑。

```rust
struct Node { next: Box<Node> }
struct Tree { children: Vec<Tree> }
```

`Node` 内部先放 `Box` 自己的固定形状，再通过它访问下一个 `Node`。`Tree` 内部保存 `Vec`，子节点内容由容器另外组织，因此布局可以有限。不过 `Node` 的例子没有给出如何结束链条。类型大小有限，还不能保证可以构造出一个有限的初始值。`Tree` 可以用空 `children` 结束递归。两种结构都能有限存放，空容器还给 `Tree` 提供了实际构造叶子的方式。

**类型大小有限，还要继续考虑具体值怎样构造、怎样结束。**

检查时可以沿着直接包含的关系往下走，并记下当前正在展开的类型。这样就能发现什么时候又回到了起点。

```rust
struct A { b: B }
struct B { a: A }
```

进入 `A`，继续看字段 `B`，再从 `B` 回到 `A`。`A` 仍在当前展开链里，于是确认直接包含成环。已经检查完成的类型可以复用结果。共享引用、`Box` 与 `Vec` 会隔开内联关系，检查在这些位置停止向目标内部展开。这一步只确定大小能否有限。字节数、对齐方式、字段偏移都可以留到后面再算。

## 不同的递归

函数可以调用自己，但检查一次调用时，通常只需要已经确定的函数签名。调用最终是否停止，要结合运行时走到的分支来看。

```rust
fn sum(n: i32) -> i32 {
    if n == 0 { 0 } else { n + sum(n - 1) }
}
```

检查递归调用时，`sum` 的签名已经知道：接收 `i32`，返回 `i32`。因此 `n - 1` 满足参数要求，返回结果也能参与加法。输入非负整数时，这段逻辑逐步接近 0。输入负数时则不能靠这个分支自然停止，还可能出现溢出。类型检查不会因为调用关系中出现环就直接按无限对象大小拒绝它。运行终止性需要另外讨论。

把它与常量和对象大小放在一起，就能看清“出现了环”为什么还不足以直接作判断。关键在于正在沿哪一种依赖继续处理。

```rust
const A: usize = B;
const B: usize = A;
struct C { next: C }
```

`A` 与 `B` 是“求值需要谁”的环；`C` 是“对象内部直接放谁”的环。数组类型再引入“确定类型需要哪个长度值”的依赖。它们都可以标记尚未访问、正在访问和已完成，但**走的是不同的边**。一个引用能隔开对象内联，却不会替常量 `A` 算出值。因此每次看到递归检查，先确认它在沿什么关系走，再判断遇到环意味着什么。
