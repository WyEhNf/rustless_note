## 控制流的结果类型

块、`if`、`loop` 和 `while` 都属于表达式，但它们组织执行路径的方式不同。这一章要同时看两件事：程序接下来走哪里，以及正常结束时能给外面什么结果。

块按语句顺序检查，并随进入和退出维护作用域。`let` 先检查初值，再让新名字生效；普通带分号表达式可以丢弃结果；最后的尾表达式给出块的类型。末尾直接跳走时，还要结合 `Never` 判断。

```rust
fn choose(flag: bool) -> i32 {
    if flag { 1 } else { return 2; }
}
```

`if` 的条件接收 `bool` 要求，两条分支接收函数尾部的 `i32` 要求。`then` 正常给出 1，`else` 的 `return` 检查整数 2 后直接离开函数，因此没有正常走到 `if` 末尾的值。整个 `if` 可以按 `i32` 使用。

## 分支结果的合并

有 `else` 时，两个正常分支需要找到共同类型，允许的适配与 `Never` 会参与判断。没有 `else` 时，还要考虑条件为 `false` 的路径；这条路没有给出额外数据，因此整个 `if` 按 `Unit` 理解，`then` 需要满足 `Unit` 或 `Never`。

给 `then` 中的整数加分号，可以把它的值丢弃；赋值本身也得到 `Unit`，适合表示满足条件时做一次修改。条件与分支的角色不同，它们接收的 `expected` 也不同。

## 循环退出与携带值

```rust
let result: i32 = loop {
    if ready { break 3; }
    break 4;
};
```

假定 `ready` 是可见的 `bool`，两个 `break` 都属于当前 `loop`，携带值都按外层 `i32` 要求检查。循环体自身要求 `Unit` 或 `Never`，`break` 自身跳走，所以具有 `Never`；它带出的整数则用来确定整个 `loop` 的结果。

没有收集到 `break` 的 `loop` 可以按 `Never` 理解。嵌套循环各自收集自己的退出值，`continue` 只进入下一轮，不贡献结果。缺少外层 `expected` 时，当前选择首个 `break` 类型的方式还可能受顺序影响，正文会保留相关边界例子。

## while 与跳转

`while` 可能一次都不执行，这里固定得到 `Unit`。条件要求 `bool`，体要求 `Unit` 或 `Never`，`break` 携带内容也要符合它的具体 `Unit` 规则。需要从循环中取得一个整数时，可以使用外部变量，或者使用支持带值 `break` 的 `loop`。

`break` 和 `continue` 需要找到当前可用的循环；`return` 则根据当前函数检查携带值，空 `return` 实际提供 `Unit`。`while` 条件的检查还会暂时隔离外层循环上下文，条件内部自己建立的循环仍可使用。

**跳转自身的类型、携带值的类型和外层表达式的结果，需要分别看。**

本章把块与 `if` 合起来讨论正常结果，把 `loop` 单独用于解释带值退出，再把 `while` 与跳转上下文联系起来。早期 `return` 后的不可达内容、循环结果选择等细节也会按当前规则的实际范围说明。
